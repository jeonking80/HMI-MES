# 조회 전용 운영 도우미

`POST /api/v1/assistant/chat`는 기존 Nemotron 공급자 설정을 사용한다. 키가 없으면 경로가 등록되지 않는다. 모델은 DB나 명령 실행기에 접근하지 않는다. 서버가 고정한 도구만 호출하며, 각 도구는 호출자의 세션 쿠키를 사용해 같은 사용자 앱의 조회 API로 GET 요청한다. 모델이 보낸 임의 URL·HTTP 메서드·설비 식별자로 경로를 만들지 않는다.

## 인증과 화면 계약

최초 요청은 `read` 권한과 세션·Origin·CSRF를 검증한다. 유휴 만료를 갱신하지 않는다. 개별 GET도 기존 조회 API의 인증·권한과 정확한 line/source/stream 검사를 다시 통과해야 한다. 게스트의 전용 계정 역시 read 권한으로 이용할 수 있다. 요청 본문, 메시지 수·길이, 도구 인자와 반복 수에는 상한이 있다.

기존 200 응답의 `answer`, `evidence`, `model`, `generated_at`은 유지한다. 401/403은 인증·권한·CSRF, 422는 잘못된 요청, 429는 한도, 502는 공급자 실패다. HTTP 타임아웃 또는 전체 시한 초과는 다음 **추가 계약**으로 구분한다.

```json
{"detail":"assistant request timed out","code":"ASSISTANT_TIMEOUT"}
```

상태 코드는 **504**다. 기본 전체 시한은 25초이며 설정값도 최대 25초다. 요청 검증·최초 권한 조회·모든 공급자 왕복·내부 GET 전체에 한 번만 적용한다. 도구나 모델 라운드마다 시간을 다시 주지 않는다. Vercel의 30초 설정은 변경하지 않았다. 시한이 끝나면 모델 답변을 생성하지 않으며 DB 작업의 중단·롤백 완료나 원격 공급자의 처리 중단까지 보장하지 않는다. 이 경로에는 생산 쓰기 작업이 없다.

## 활성 알람 도구

추가 도구는 인자가 없는 `get_active_alarms`다. 태그 사전 48개 태그의 고정 그룹(`Line`, `Infeed`, `Sealer`, `Outfeed`)마다 다음 기존 조회 API를 호출한다.

```text
GET /api/v1/alarms?line_id=…&source_id=…&stream_id=…&asset_id=…&view=attention&limit=100
```

`attention`에는 복귀했지만 확인하지 않은 알람도 있으므로 응답의 `ACTIVE_ACKNOWLEDGED`와 `ACTIVE_UNACKNOWLEDGED`만 활성 수에 포함한다. 설비마다 조회 상태·활성 수·미확인 수·심각도별 수·최대 10개의 식별자 요약·설정/소비자 확인 상태를 보낸다. 원문 알람 증명과 조치 메모는 모델에 보내지 않는다. 모델용 도구 결과는 12,000바이트 상한을 지킨다.

한 설비에서 읽는 것은 최대 100개짜리 한 페이지다. `has_more`이면 `complete: false`, `counts_basis: OBSERVED_PAGE`로 표시하므로 전체 수로 주장할 수 없다. 서버가 아직 지원하지 않는 Infeed/Outfeed의 404 또는 인증·조회 오류는 `active_count: null`과 오류 상태로 남긴다. 이를 활성 알람 0개로 바꾸지 않는다. 각 설비 GET의 도구 이름·라벨·HTTP 상태·조회 시각은 기존 `evidence` 배열에 기록한다. 현재 Line/Sealer만 구현되었으므로 전체 설비를 포괄하는 `complete`는 false일 수 있다.

트렌드 도구는 태그를 기존 API의 반복 `tag` 인자로 전달하고, 60분 이하는 second, 더 긴 기간은 minute 해상도를 명시한다. 모델 도구 스키마에 없는 인자·지원하지 않는 태그·쓰기 도구는 서버에서도 거절한다.

## 요청 제한 선택과 서버리스 한계

CX-13의 허용된 선택지 중 기존 프로세스 메모리 방식을 유지했다. 추가 DB 마이그레이션은 없다. 동일 프로세스 안에서 300초 동안 세션별 10회, 전체 30회를 원자적으로 세고, 게스트 전용 계정은 모든 게스트 세션을 합쳐 **2회**로 제한한다. 같은 게스트가 세션을 새로 발급받아도 이 계정 버킷은 그대로 적용된다. 요청 실패와 공급자 오류도 시도 한도를 소비한다. 게스트가 아닌 조회 사용자에는 기존 세션·전체 한도를 유지한다. 설정값은 유한한 양수·정수와 최대 범위를 검증한다.

**이는 여러 Vercel 인스턴스에 걸친 강한 합계 제한이 아니다.** 프로세스마다 별도 버킷이 있으며 재시작·콜드 스타트에서 사라진다. 인스턴스가 늘면 전체 허용량과 게스트 합계도 늘 수 있다. 무료 공급자 키의 모든 사용량을 이 제한 하나로 보장하지 않는다. 강한 분산 제한이 필요하면 별도 승인된 DB/공급자 측 한도 설계가 필요하다. 이 작업은 공개 배포 설정이나 요금 정책을 바꾸지 않는다.

## 로그와 검증 범위

프롬프트·응답 원문·키를 애플리케이션 로그에 남기지 않는다. 공급자·도구 오류 내용을 사용자에게 그대로 내보내지 않는다. URL의 사용자명·비밀번호·쿼리·fragment에 공급자 자격 증명을 넣는 설정도 거절한다. 캡처 로그 시험은 성공, 공급자 오류, 시간 초과, 도구 오류에 비밀 테스트 문자열이 나오지 않는지 확인한다.

로컬 검증:

```sh
.venv/bin/python -m pytest tests/unit/test_assistant_bounds.py tests/integration/test_assistant.py -q
```

모델 응답은 `httpx.MockTransport`로 주입한다. PostgreSQL과 ASGI로 호출자 권한·기존 조회 경로·게스트 계정 한도를 확인하지만 실제 Nemotron 공급자를 호출하거나 실제 키·외부 요금·응답 품질을 검증한 것은 아니다.
