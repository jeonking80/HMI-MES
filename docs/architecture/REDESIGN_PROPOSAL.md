기준 main `bae8599`, 2026-10-26. **승인 전 설계안**. 제품·AGENTS·기획서 원문은 이번에 변경하지 않았다. [전체 진단](../work-orders/reports/CX-44.md), [실행 계획](RECOVERY_PLAN.md).

## 3. 시간·증거 재설계 원칙

- 수집 시각, API 수신 시각, PLC source/server 시각, gateway monotonic 순서, 통신/값 품질을 각각 저장한다. 수신 시각을 설비 발생 시각으로 이름 바꾸지 않는다.
- 수량 확정(`quantity_status`), 시간구간 확정(`time_status`), 원본 보관(`raw_status`), 재계산 가능성(`replay_status`)을 분리한다. `SETTLED` 하나로 모두 참을 뜻하게 하지 않는다. 수량정산 성공+시간 일부 UNKNOWN도 유효한 결과다.
- 수집 시점에 canonical time/불확실성/방법/정책버전/품질/실행 귀속을 정규화한 작은 사실을 원자적으로 확정한다. 보고서는 전체 48태그 JSON을 조회시 다시 hash 검증하지 않는다. 변경 불가 사실의 digest는 훼손 탐지의 연결값이지 삭제된 표본을 복원하는 증거는 아니다.
- gateway 순번과 수신 경계로 `UNKNOWN`의 소유 구간을 제한한다. 시간 보정 불가 표본은 해당 epoch/실행/수신 순서 범위의 UNKNOWN이며 모든 미래 UTC 기간의 UNKNOWN으로 전파하지 않는다. 이는 모든 가능한 옛 UTC 주장을 미래까지 보수적으로 덮는 현재 보장보다 약하다. UI에는 `시간 배정 불가`와 해당 실행/세대 및 누락 수를 남긴다.
- 실행 시작·종료 또는 사건 생성 시간 기준 최대5분 단위로 구간을 봉인한다. 시간별 요약은 이미 봉인된 구간을 재집계하며 미봉인 사건을 1시간 쌓지 않는다. 봉인에는 running/stopped/unknown 합, 수량합, 품질 coverage, 최초/최종 순번, 정규화 정책, 미해결 원인, digest를 둔다. `running+stopped+unknown=covered_duration`을 보장한다. 일별/실행별 봉인 결과는 raw 삭제로 바꾸지 않는다.
- 봉인된 교육용 보고서는 3시간(원본 보관 창) 내 지연 도착만 자동 개정한다. 창 밖 복구는 자동으로 과거 확정을 뒤집지 않고 재처리 요청/별도 버전으로 다룬다. 미해결 데이터를 정상으로 바꾸지 않는다. 무제한 과거 재계산을 포기한다는 계약 변경이다.
- 알람은 모든 capture의 판정 영수증 대신 현재 qualification 상태+순번 frontier를 고정 크기로 덮어쓰고, 발생/복귀/ACK/메모/규칙변경/불명 진입·회복만 이력으로 보관한다. 3시간 내 판정 재생은 raw에서 가능하고 그 이후 표본별 판단 재현은 보장하지 않는다. chatter도 사건 수 quota에 포함한다.
- same-host는 실제 API와 gateway가 같은 kernel인 로컬 구성에서만 허용한다. 공개는 RTT 또는 명시 교육용 수신 기준 모드. 후자는 UTC 발생 정확도·장시간 단절 중 경과시간·과거 알람 정밀 시각을 약화하며, 품질/통신 UNKNOWN과 제어 안전 원칙은 유지한다.

## 5. 추천 B의 데이터 예산 — 실측이 아닌 설계 상한

`0.5GB`는 보수적으로 **500,000,000 bytes**로 계산한다. 무료 서비스 실제 과금 지표가 relation+index/DB논리크기/기타 중 무엇인지 확인 전 배포 보장이라고 부르면 안 된다. 이하 입력 크기는 원본 평균6.5KB를 측정했다는 주장이 아니다.

운영 포락선: 라인1/수집stream1/48태그1Hz(정상 생성률1Hz; WAN 복구는 별도의 bounded 묶음 접수로 신규 포함7건/초 이상 목표, burst도 전체 예약 예산 안에서 처리), 캡처+시각 proof+ACK를 정규화한 레코드 총8KiB 이하, 생산/상태 사건 합 초당최대8개·개당8KiB 이하, 미봉인 구간최대5분, 활성 실행1개·실행별 요약 크기 상한; 장시간 실행은 동일 execution_id 안에서 5분 구간을 봉인, 미해결 업무최대32개. 실행을 바꾸지 않고 무기한 수량을 늘리는 보장은 두지 않는다. 명령/메모/설정 payload와 문자열 길이·개수도 아래 슬롯 크기로 강제한다. 허용 생성률을 위반하거나 상한보다 큰 batch는 ACK하지 않고 명시 오류/손실 구간으로 기록하며 무제한 quarantine 본문을 저장하지 않는다.

위 숫자로 곧바로 PostgreSQL 물리 상한을 증명한 것은 아니다. 슬롯은 압축 후 평균값이 아닌 검증 가능한 최대 직렬화 크기이며, 인덱스·TOAST·page bloat·catalog 비용이60MB/교체여유120MB 안에 드는지는 대표 데이터와 공개 수명주기 시험으로 검증해야 한다. 구현에는 전체 table를 quota registry에 등록, 고정된 partition pool의 주기 교체/재사용, 동시입력 총예약, page/relation 실제크기 경계, 미정리 backlog 예산, vacuum 정상성을 포함한다. cleanup 실패 시 TTL을 기다리며 계속 INSERT하지 않고 **다음 증가 전** 예산 검사를 통과해야 한다. 400MB에서 조기경보, 452MB보다 작은 구현별 preallocation경계에서 신규업무를 막고 남은여유로 마지막정리한다. 정확한 경계는 최악 transaction 증가량을 측정한 뒤 확정한다. 제품 구현/물리측정 없이 “무료0.5GB보장 검증완료”라고 보고하지 않는다.

### 5.1 연속 1Hz와 접수 제한은 다른 보장

- **정상 포락선 안**(위 rate/크기, 미해결32건이하, seal/prune 서비스가 입력보다 빠름)에서는 1Hz를 계속 받아들이며 위 상한에 수렴하도록 설계한다. 이것이 연속 운영 보장이다. 슬롯주기 초기·종료 순간과 burst 포함 기준을 검증해야 한다.
- **무제한 미해결·장애/폭주**에서는 유한 저장·모든원본영구보호·무중단생산을 동시에 보장할 수 없다. 추가 생산/명령/설정의 접수를 거절해 상한을 지키는 것은 저장 안전 보장일 뿐 연속1Hz수락/생산 보장이 아니다.
- 아직 실행 중이어도 5분 단위 검증된 사건합+연속순번 frontier를 원자적으로 봉인해 이전 사건본문을 교체할 수 있어야 한다. 실행 종료까지 모든 원본을 보호하면 예를 들어 8시간×8/s×8KiB만으로 예산을 넘긴다. 실행 시간 제한·자동 종료를 새로 도입한다는 뜻은 아니다. 시간UNKNOWN이 있으면 그슬롯/수량합/미해결사유를 그대로봉인하고 SETTLED로바꾸지않는다.
- active 실행이 이미 quota를 예약받았더라도 통신누락으로 5분 봉인이 불가능하면 생산확장을 제한하고 이후 초당 관측만 고정 ring에 받는다. 못받은 사건은 **최초·최종손실순번+사유·불명상태**로 bounded summary에 기록한다. 기존 불명원본은 보호예약에 유지하며 무제한새본문은 기록하지 않는다. 요약범위확장은 더정밀한구간정보를 잃는다고명시한다.
- 감사/알람/명령 receipt도 unbounded여서는안된다. quota도달후 완료 상세를교체하거나 새접수거절; 거절요청자별ID를무한감사하지않고 bounded오류카운터/시간범위만갱신한다. ACK가 필요한이미접수된명령은예약영역에서처리하고 result UNKNOWN을성공으로만들지않는다. 운영자가다시실행하는새ID를자동발행하지않는다.
- 외부 archive를선택하면 export bundle/manifest hash/행수/seqcoverage를대조하고 읽기복원성공후hot참조를삭제한다. 외부실패시무한대기열이아니라정해진유예/접수제한이발동한다. 외부도유한quota·TTL·월비용상한을정하고, archive영구보존은위상한의포함대상이아니며무료보장도아니다.

### 5.2 lifetime 중복정확성과 유한 저장의 교환

현재처럼 임의batch_id를이후어느generation/seq로제출해도영원히기억해서거절하려면영구집합이필요하다. 유한상태로임의무한집합에대한정확membership을보장할수없다. 추천은 `(registered active generation, capture_seq)`를수집의canonical identity로하고generation회전시이전쓰기자격을폐기한다. 5분 업무 봉인 watermark와 3시간 capture/idempotency 폐기 watermark를 분리한다. 최근 3시간 창 안에서는 업무 봉인 여부와 무관하게 원래 ACK를 재생하고 digest 충돌을 검사한다. 폐기 watermark 이하에서만 원래 ACK 재생/다른 본문 충돌 세부 판정 없이 `410 WINDOW_EXPIRED`로 거절한다. 최근창내에서만digest충돌과원래ID영수증재생을보장한다. 과거임의batch_id를새seq로재활용했는지전수검사하는보장은없어진다. command/execution도서버발행active-session ID+유한회복창을쓰고, 창밖결과불명은자동새ID재실행하지않는다. Bloomfilter는오탐으로정상입력을거절하므로정확보장을유지하는대안으로제시하지않는다.

## 6. AGENTS 원문과 제안 문장

AGENTS는원본영구보관을명시하지않는다. 원본수명단축자체를불변조건위반이라고주장하면과장이다. 다만24행의중복제거범위와25행의불명보호를명확히하려면아래변경을**승인될계약변경**으로기록한다.

- 원문 `AGENTS.md:24`: “생산 사건은 원래 execution_id에 귀속한다. 중복 제거·실적·처리 커서, 시뮬레이터 물품·수량·사건은 각각 원자적으로 저장한다.”
- 변경안: “생산 사건은 원래 execution_id에 귀속한다. 허용된 활성 세대와 보관 창 안의 중복 제거·실적·처리 커서, 시뮬레이터 물품·수량·사건은 각각 원자적으로 저장한다. 재전송 보관 창의 폐기 watermark 이하 또는 폐기된 세대의 재전송은 만료로 거절하며 새 실적으로 적용하지 않는다. 업무 봉인과 무관하게 보관 창 안에서는 원래 영수증 재생·중복 검사를 유지한다. 원본 만료 후 표본별 재검증·원래 영수증 복원 및 과거 batch_id의 전역 재사용 검출은 보장하지 않는다.”
- 원문 `AGENTS.md:25`: “품질 불명·통신 단절·영구 누락을 정상 값·정산 완료로 대체하지 않는다.”
- 변경안: “품질 불명·통신 단절·영구 누락을 정상 값·정산 완료로 대체하지 않는다. 수량 정산, 시간 품질, 원본 보관 여부를 분리하고, 불명은 해당 실행·세대·순번 및 확인 가능한 수신 경계의 범위로 기록한다. 원본 보관 만료만으로 이미 봉인된 사실을 정상 또는 불명으로 바꾸지 않는다. 미해결 기록은 예약된 유한 예산에서 보호하며 예산 소진 시 새 업무를 거절하고 손실 범위와 제한 사유를 남긴다.”
- 추가안: “공개 교육운영의 데이터는 승인된 종류별 기간·건수·바이트 예산 안에서 보관한다. 일반 사용자의 수정·삭제는 금지하고, 완료·봉인된 기록만 승인된 보관 연산자가 수명주기 정책에 따라 삭제한다. 봉인 요약에는 당시 품질·미해결 사유·계산 버전을 보존한다. 용량 제한을 위해 미해결을 성공 처리하거나 결과 불명 명령을 새 ID로 자동 재실행하지 않는다.”

22·23·26행의두앱분리/OPC/PLC판정/명령불명/인증권한은유지한다. 18행의기준변경사유기록을따라기획서7/90/180일→24h/30일/quota우선 교육프로필 및검증한계를명시하며기존T항목을통과로재표기하지않는다.

## 7. 이관과 승인 뒤 검증 요구사항(이번 수행은 미실행)

1. 공개현황 read-only 인벤토리(테이블/인덱스/행수/종류별증가량, event·alarm·audit 포함)와 기존실행별 수량/시각/누락/원본유무 목록을확보한다. DB DSN없음으로현재차단;과거18초보고는Claude기존관측이며이번실측이아니다.
2. 기존증거를날짜만으로정상으로승격하지않는다. 현재재구성가능한구간만legacy봉인하고, 이미원본이없거나시각이불명인실행은unknown/legacy-unrecoverable와그이유를보존한다. 봉인manifest와정책버전을별도저장한다.
3. 새모델을별도읽기 projection으로만들어동일구간 수량합·시간합·누락·사유·SPC·알람전이를대조한다. 기존history와newprojection의읽기전환을가역적으로만든뒤수명주기를적용한다. 원본삭제후코드rollback만으로원본은복원되지않으므로삭제전export/restore검증또는원본복원불가를명시해야한다.
4. 원본만료 전후 동일 실행/일일 보고값은 봉인version이같으면동일해야한다. raw_status만EXPIRED로바뀌며전체future보고UNKNOWN전파는없어야한다. 진짜통신/시간불명구간은보존한다.
5. 공개24시간1Hz·여러실행·원본3h경계·분rollover·날짜경계·사건late/outoforder·규칙변경·runtime재시작·알람chatter·미해결quota32/33번째·overpayload·archive실패·cleanup중단을검증한다. 핵심은정상1Hz수락률과“저장안전위한거절”을별도집계하는것이다.
6. 30일을기다리지않는시간주입/작은동등quota장기수명주기시험으로모든관계·인덱스·TOAST·manifest·보호행이상한에머무는지확인하고,공개물리용량추세는최소24h실측한다. 작은quota시험과실제30일시험을혼동하지않는다. 기존기획전체7/90/180일수락은B교육프로필로대체완료가아니며별도로미충족이다.

## 제안 모델의 운영 경계

원본 보관 창은 정상 캡처 생성 시간에 대한 정책이며, 오래 단절된 backlog를 수신 즉시 버리거나 현재1Hz 제한으로 복구를 굶기지 않는다. 미적용 사건은 먼저 수량/커서 원자 반영 또는 미확정 보호 슬롯에 귀속하고, 봉인·대조가 끝난 구간만 정리한다. 한 번의 복구 묶음 최대크기와 동시 transaction 예약은 H 예산에 포함한다. 3시간보다 긴 단절·최대8/s 사건 burst가 보호 예산을 넘으면 자동 복구 가능 범위를 보장하지 않고 명시적 손실·미확정 상태로 남긴다. 그 제한은 원기획 보장 변경으로 검토해야 한다.

보관 중 재계산 결과가 바뀌면 기존 봉인행을 조용히 수정하지 않고 새 버전으로 append하고 구버전도 정해진 슬롯 내 보존한다. source·generation·epoch·규칙 버전의 폐기도 영구 tombstone 예외를 만들지 않으며, 현재 등록된 자격·단조 순번으로 폐기된 scope를 거절한다. 삭제된 본문 해시는 그 본문을 복원하거나 독립 검증할 수 있다는 의미가 아니다.

추천 B의 최종 완료는 승인된 교육 프로필 기준이다. 원래 7/90/180일 보관을 유지하는 전체 완성은 C의 무료 보관 용량·조회·복원 경로를 먼저 확보해야 하며, 확보 전에는 완료 일정이나 무기한 무료 운전을 약속하지 않는다. 모든 신규 24시간·8시간·30분 단절 시험은 계획만 제시했으며 별도 승인 전 실행하지 않는다.

SQLite도 별도 유한 예산이 필요하다. 위 452MB 계산은 Neon에만 해당한다. 게이트웨이는 현재 50MB 제한과 원래 순번/전송 대기/누락 근거를 유지하면서 봉인 ACK 이후만 정리하고, simulator는 원기획 7일 사건 보관 및 미완료 실행 보호를 로컬 디스크 예산과 대조해야 한다. command_journal·완료 실행·로그·인증 감사·백업도 기간/건수 제한에 포함한다. source SQLite의 사건 삭제는 공개 실적 커서·복구 창 대조 없이 앞당기지 않는다. 로컬 공간을 무한 무료 archive로 간주하지 않으며 호스트 디스크 부족과 보호자료 포화는 독립 경보/신규 업무 제한 조건이다.

사건 8/s는 생성 시간 기준이다. 복구 시 초당7 capture를 접수하면 사건 최대56/s를 처리할 수 있어야 하며, 함수/transaction별 bounded chunk로 커서 적용·5분 생성 구간 봉인을 전진시킨다. backlog를 전부 메모리나 미봉인 DB 행으로 쌓지 않는다. 기존 보관 창에 필요한 replay와 이미 업무 봉인된 사건의 재전송 확인은 별도 폐기 watermark를 적용한다. 이 처리량은 구현 후 목표 호스트/WAN에서 측정할 수락 조건이며 현재 달성한 값이 아니다.
