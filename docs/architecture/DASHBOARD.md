# 대시보드 요약

`GET /api/v1/dashboard?line_id=&source_id=&stream_id=&date=YYYY-MM-DD`는 CX-05 고정 계약을 따른다. `create_user_app`에 등록하여 로컬·Vercel에 같은 경로를 제공한다. 인증된 `read` 권한 트랜잭션을 사용하며 유휴 만료를 연장하지 않는다. 엄격한 query 검증과 `Cache-Control: no-store`를 적용한다.

수량·가동/정지/불명·24개 서울 시간대 구간은 `reports.read_daily_report`를 재사용한다. 대시보드의 명시적 source/stream만 조회한다. 여러 수집원이 한 라인에 존재하는 경우 라인 전체 일일 보고와 이 범위 차이를 구분한다. 수량은 JSON 문자열이고 시간은 UTC Z이다. 잠정 수량의 기준은 `RECEIVED_EVENTS`이며 잠정 여부는 일일 보고를 따른다.

현재 수집·생존 신호는 기존 `read_snapshot`의 기준을 사용한다. 미관측이면 `NO_DATA`, 48개 표본과 생존 신호가 정상일 때 `LIVE`, 지연·품질 저하·충돌·시간 역행 등 나머지는 `STALE`이다. 기존 3초 지연·5초 생존 신호 경보 판정을 완화하지 않는다. 마지막 수신 시각은 현재 gateway/generation에 속하는 마지막 배치의 저장 시각이며, 그 시각만으로 `LIVE`를 판정하지 않는다.

현재 실행은 최신 사용 가능한 캡처의 실행 ID를 정확한 line/source/stream의 등록 실행과 대조한다. 실적은 원래 실행의 누계다. 품목은 실제 작업지시 연결 원장과 일치하는 경우에만 표시하고, 같은 이름의 미연결 작업지시에서 가져오지 않는다. 미관측·지연·실행 없음은 `active_execution: null`이다. 알람은 현재 발생 기록에서 활성과 미확인을 별도로 세며, 심각도 키는 원래 규칙의 식별자를 그대로 쓴다. 다른 수집원의 알람은 합하지 않는다.

하나의 응답을 만드는 동안 라인의 공유 잠금으로 수집 커밋과 경합을 조정한다. 반환 JSON은 UTF-8 64KiB 상한을 검사한다. 과도한 심각도 종류 등으로 상한을 넘으면 일부 통계를 숨기지 않고 503으로 거절한다.

`oee_partial`은 기존 기획에 추가된 포트폴리오 참고 지표다. 가용률은 불명을 분모에 포함한 가동 비율, 품질률은 양품/(양품+불량)이며 생산이 없으면 null이다. 이상적 사이클과 계획 생산시간의 합의가 없으므로 성능효율은 null, 설명은 `PERFORMANCE_NOT_DEFINED`로 고정한다. 이를 완전한 OEE로 표시하지 않는다.
