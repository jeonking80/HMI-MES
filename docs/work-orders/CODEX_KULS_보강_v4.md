## CX-23. 30분 단절 후 회복 결함 (CX-19 후속)

**현상(CX-19 run4):**
- 재연결 후 300초 안에 회복하지 못했다.
- 회복 마지막에도 큐 13,804,138바이트, pending 836, inflight 1이 남았다.
- verified cursor 4, recoverable gap 5–10.
- 최종 정산에 도달하지 못했다.
- 큐 100MB 증폭은 `e571358`로 해소됐다.

**요구:**
1. 실제 30분 시험을 반복하기 전에 **약 1,800개 대기 배치의 전체 복구를 짧게 재현**한다(인계 메모 그대로). 다음 병목을 측정해 보고서에 수치로 남긴다.
   - 배치당 처리 시간
   - 배치 크기
   - 트랜잭션 시간
   - 게이트웨이 전송 간격·동시성
   - API 처리량
   - recoverable gap 재조회 비용
2. 원인을 고친다. 다음 원칙은 바꾸지 않는다.
   - 중복 제거·실적·커서의 원자 저장
   - 원래 execution_id 귀속
   - 누락·불명의 정상 대체 금지
   - 30분/100MB 한도
   - 300초 회복 기준
3. 수정 뒤 짧은 재현으로 목표 처리량을 확인한다. 그다음 **실제 30분 단절 시험을 1회** 실행한다. 통과·실패를 그대로 기록한다.
4. 시험 실행기에 붙였던 임의 기준(예: 이전의 tick ≥17,800)을 다시 넣지 않는다.

## CX-24. T01~T12 단일 묶음 수락 (CX-17 후속)

- 한 커밋에서 T01~T12 전체를 **한 번의 실행 묶음**으로 돌린다. 분할 17개를 합산하지 않는다.
- 묶음에는 다음을 포함한다.
  - 브라우저 경계: T02·T03 UNKNOWN 표시·T04·T05·T06
  - T09: 전체 재시작에서 명령·열린 알람 대조
  - T12: 전체 `backup_set_id` 복원
- 산출물: 대상 SHA·dirty 여부·T별 assertion·JSON/JUnit. 실패가 있으면 고치고, 기준을 바꾸지 않는다.
- 결과는 `docs/ACCEPTANCE_EVIDENCE.md`와 `reports/CX-24.md`에 반영한다. 묶음 전체가 통과해야 "T01~T12 결합 수락 통과"로 표시한다.

## CX-25. 7일 이력 조회 성능 실측 (CX-20 후속)

- CX-20 실행기로 기본 보관 규모(9개 아날로그 × 604,800초 = 5,443,200행)를 로컬 일회용 DB에 적재한다.
- 태그 4개·24시간 질의를 동시 10명으로 측정한다. 목표는 p95 ≤ 3초다.
- p50/p95/max, 표본 수, cold/warm, 쿼리 계획, DB·인덱스 크기, 하드웨어 사양을 기록한다.
- 목표를 넘으면 원인을 고친다. 응답 값은 바꾸지 않는다. 공개 DB와 공개 보관 프로필로 대체하지 않는다.
- 디스크 여유를 먼저 확인한다. 부족하면 실행하지 않고 필요한 용량을 보고한다.

## CX-26. clean build 릴리스 실행 (CX-22 후속)

- CX-22 실행기를 `--run`으로 실행한다. 다음이 모두 포함된다.
  - no-cache build
  - image manifest
  - Compose 전체 실행
  - 데이터 보존 재시작
  - 독립 실행
- 과거 ENOSPC 원인을 먼저 정리한다. 공간 guard가 막으면 그 사실과 필요한 용량을 기록한다.
- 기존 이미지 runtime이나 과거 build를 이번 성공으로 대체하지 않는다.
- 결과로 릴리스 manifest(대상 SHA·image ID·실행 결과)를 남긴다.

## OPS-03. 공개 실연과 runtime 금지 DML 실측 (OPS-02 후속)

**선행 조건:** Codex 환경에 공개 source와 이어진 보호된 영속 runtime(게이트웨이·시뮬레이터 SQLite, 인증서, 서비스 토큰)이 있을 때만 진행한다. 없으면 **실행하지 않고** 무엇이 없는지 보고한다. 새 source·generation을 만들거나 기존 SQLite를 초기화하지 않는다.

1. **공개 실연:** [PUBLIC_DEMO_RUN.md](../architecture/PUBLIC_DEMO_RUN.md)·[OPS-02_CLOCK_MIGRATION.md](../architecture/OPS-02_CLOCK_MIGRATION.md)대로 `--clock-measured-round-trip`으로 짧게(약 5분) 운전한다. 시작·종료 전후 DB 용량을 기록한다. 무료 0.5GB를 넘기지 않는다. 다음을 확인한다.
   - 새 캡처의 트렌드 GOOD
   - 가동 > 0
   - 불명 근거
   - 원래 실행의 수량 대조
2. **runtime 실측:** `hmi_app` 연결로 신규 테이블 조회와 금지 UPDATE/DELETE/TRUNCATE/DDL 거절을 명시적 트랜잭션에서 실행하고 롤백한다. 대상은 0017·0018 테이블이다. 연결을 쓸 수 없으면 미실행으로 기록한다. 카탈로그 조회로 대신하지 않는다.
3. 결과는 `reports/OPS-03.md`에 남긴다. 공개 화면 결합 확인은 Claude에게 요청한다.
