## 남은 실제 결함

`e571358`의 gateway 수정은 recoverable gap 크기로 ReadEvents 조회량을 제한한다. API ACK가 지연되는 동안 같은 인접 사건을 과다 재전송하던 문제를 줄였다. 수정 후 실제30분 단절 run4의 최고 queue payload는28,494,088바이트로100MB 증폭은 사라졌으나 회복 마지막에13,804,138바이트·pending836/inflight1이 남았고 verified cursor4·recoverable gap5–10으로 **300초 회복 목표를 충족하지 못했다**. 최종 정산 단계에도 도달하지 못했다. loss record4개를 정상 복구로 숨기지 않는다.

향후 이 문제를 다시 맡게 되면 먼저1,800개 대기 배치의 전체 복구를 짧게 재현하여 처리량·트랜잭션/통신 병목을 측정해야 한다. 그 검증 없이 실제30분 시험을 반복하지 않는다. 이는 인계 메모이며 이번에 새 시험을 실행하라는 지시가 아니다.
