## 수정한 복구 병목과 남은 손실

`e571358`의 gateway gap 범위 제한으로 같은 인접 사건의 과다 재전송·100MB 큐 증폭을 줄였다. 그 후에도 run4는300초 복구 목표에 실패했다. 재개 후1,800개 전체 배치의 짧은 재현으로 화면 조회가 과거 ingest_batches 전체를 읽는 동안 Line 공유 잠금을 길게 보유하는 병목을 확인했다. `fc6296e`는 snapshot/screen 두 경로에서 기존 완전 capture fast path를 사용한다. 관련22개 회귀·독립 high 검토·대표 복구205.780613초를 확인한 뒤 실제 run5를 수행했다.

run5에서 원래 사건5–12는 source 재조회로 복구됐지만 30분 age limit으로 삭제된 **240개 태그 관측 이력은 복구되지 않았다**. 큐 한도·공정·1Hz 수집·300초 기준을 늘리지 않았다. 이전 실패·중단·잘못된 fixture도 [복구 보고서](CX-19.md)에 보존했다.

## 반영 범위와 정리

- 제품 변경: 복원 DB의 지속 복구 차단, gateway gap 조회 범위 제한, snapshot/screen 완전 capture fast path, Compose 웹 polling 빌드 설정.
- 도구: 전체 백업/복원, T01~T12 수락, 실제 단절/장시간, 7일 이력 성능, clean release 실행기.
- UI·UX·README·`vercel.json`·Claude 소유 브라우저 검사 스크립트·`AGENTS.md`는 변경하지 않았다.
- 시험용 CLI·브라우저·일회성 PG는 실행기에서 정리했다. 기존 preview DB와 보호된 실습 runtime은 유지한다. 자격 증명·DB dump·사용자 계정 자료는 저장소 증거에 포함하지 않는다.
- 이번 작업은 브랜치로 인계한다. main 병합과 공개 배포 완료로 표시하지 않는다.
- 공개 OPS-02는 writer 정지·전체 백업·0018 이관·실제 hmi_app 권한 검사·Vercel opt-in 재배포·짧은 실연·무료 용량 확인 순서로 인계한다. ready:true만으로 이관 완료를 주장하지 않는다.
- CX-20의 약10.47GB DB는 **일회성 로컬 성능 fixture**다. 공개 Neon 무료 DB에 적재하지 않았고, 공개6시간/14일 보관 프로필이나 실제7일 수집 근거로 대체하지 않는다.
