# CX-37 — 품목 마스터와 등록 참조

item_master의 ID/이름/단위/enabled와 목록·등록·단건 조회 API를 추가했다. 등록과 CREATE 감사는 원자적이며 ID+동일 내용 재요청은 원래 결과를 반환한다. read 조회와 production_manage+session/Origin/CSRF 등록을 구분한다. 이번 요청의 목록/등록 범위를 유지해 수정·사용 전환·삭제 API는 추가하지 않았다.

공통 recipe/work-order writer에서 schema21의 새로운 등록만 실제 enabled 품목을 요구한다. 수동/자동 발급 모두 같은 검사를 거치고, 이전 ID/영수증 재조회와 구schema 동작은 유지한다. bind·실행·정산 정책은 변경하지 않았다.

0021 이관은 기존 두 등록 테이블의 서로 다른 품목을 origin=MIGRATION/name=id/unit=EA/enabledtrue로 backfill하고 FK를 추가한다. 이는 알려진 실제 이름/단위라는 뜻이 아니다. 원래 정의/수량/영수증/counter/audit는 보존한다. master/audit는 SQL로 불변이며 최소 runtime SELECT/INSERT grants와 정확한20→21 HTTP batch를 준비했다. 사용 후 downgrade는 거절한다. 공개 적용·전체 백업/복원은 이번 범위에서 실행하지 않았다.

ITEM_MASTER.md에 동작·기준 변경 이유·이관·롤백·Claude UI/seed 후속을 기록했다. 등록 조건이 바뀌므로 해당 시험 fixture는 실제 품목을 명시적으로 등록하게 고쳤다. globally 자동 생성하거나 unknown 품목 검사를 완화하지 않는다.

검증 결과는 아래에 기록한다. 구현/시험은6.1-sol medium, DB 이관·참조/권한 검토만 high다. 검토에서 SELECT FOR SHARE가 runtime UPDATE 권한을 요구하는 충돌을 찾아, 불변 테이블에 맞는 plain SELECT로 수정했다. 공개 DB·runtime·WO-T1·UI·생산·배포는 변경하지 않았다.

14차 계약을 함께 넘기는 시점에 STATE_MACHINES.md·PLC.md·SIMULATOR_CONTROLLER.md의 예전 ‘RUNNING 설정 거절/PAUSED 새레시피/명시 END만’ 설명도 CX-33~35의 확정 동작과 맞췄다. 변경 이유·기존 안전 조건·동일 실행 근거와 상세 문서 링크를 그 문서에 명시했다. 추가 제품 동작 변경은 없다.

최초pytest1회: item/API/이관, work_orders/HTTP, 수동·자동등록ID/HTTP, workflow/cancel/read, queue/이관, 시작예약·속도조정, 실제 gateway pipeline, 게스트, 기존 등록 runtime grants/Neon batch를 묶어 **345통과/fixture1오류,379.44초**. 추가 실패는 없고 기존 websockets deprecation 경고2개였다. Ruff 자동 정리가 이름이 다른 fixture 별칭 import를 제거한 것을 놓쳐 신규 head21 큐 확인1개가 fixture를 찾지 못했다. 같은 이름의 명시적 fixture 재노출로 고치고 그1개만 재실행해 **1통과,5.86초**. 제품 추가 변경은 없다. 전체346개를 한 번에 통과했다고 표시하지 않는다.

변경 Python23개 Ruff check --fix1회는2건 자동 정리 후 남은 오류0, format --check1회23개 통과. 이후 fixture import 보정 뒤 검사는 반복하지 않았다. 로그 `/tmp/hmi-cx37-tests.log`, `/tmp/hmi-cx37-fixture-recheck.log`.

검증에는 실제 hmi_app의 item→recipe→work-order 등록과 item UPDATE 권한 없음, SQL FK/불변 근거, 정확한 schema20 backfill·기존 receipts/counters/audit 보존, rendered/Alembic catalog 비교, 사용후 downgrade 거절, 원래 API 멱등성과 동시 등록, 이전 schema roundtrip, head21에서 큐 변경/원래 receipt 재조회가 포함된다.

## 전달 범위와 남은 작업

CX-31~37을 각각 codex/kuls-backend-v3에 나눠 반영한다. 기존 두 E2E 파일의 미커밋 변경은 그대로 두었다. 프로젝트 전체 수락/운영 완료를 주장하지 않는다. 8시간 시험은 실행하지 않았다.

Claude는 현재 공개 revision을 먼저 확인하고 필요한 순서로19 upgrade→19 grants→20 upgrade→20 grants→21 upgrade→21 grants를 적용한다. 각 batch의 시작 revision/owner guard를 임의로 건너뛰지 않는다. UI parser/선택·대기열 화면/seed와 API·gateway·simulator 계약을 맞춘 뒤 배포·공개 확인한다. SQLite storage4/runtime3 전환은 기존 보호된 SQLite·인증서·토큰을 보존하는 정상 운영 절차로 수행해야 한다. 이 작업에서는 공개 적용이나 runtime 재시작을 하지 않았다.

CX-33/CX-35의 최초 Ruff 지적을 수동 보정한 뒤 재검사하지 않은 기록은 각 보고서에 그대로 남긴다. 이번 검사 통과로 그 미실행을 소급해 통과 처리하지 않는다.
