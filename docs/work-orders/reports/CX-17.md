# CX-17 — 결합 수락 실행기

2026-10-23 UTC. 기준 HEAD `4490a4cbef7c46e5dff9017d059ddc6b312df161`, 실행 시 dirty=true. 이 보고의 현재 확정 결과는 core 6개 시나리오이며 전체 T01~T12 완료 판정은 아니다. 브라우저와 재시작/전체 복원 결과는 각 담당의 최종 실행 근거를 통합해야 한다. 공개 DB·기존 preview PostgreSQL·보호된 로컬 설정을 변경하지 않았다.

## 실행기와 판정 근거

`tests/e2e/conftest.py`는 기존 `tests/integration/conftest.py`의 일회성 PostgreSQL과 `test_gateway_pipeline.py`의 실제 암호화 OPC/인증 HTTP socket fixture를 재사용한다. 기존 개별 test 함수를 호출해 T 통과로 포장하지 않는다. 새 시나리오가 명령·원본 사건·최종 순번·정산·보고서를 한 실행에서 대조한다. 이 fixture의 API와 simulator는 동일 시험 프로세스 안에서 실행하며 **CLI 프로세스 재시작을 검증했다고 주장하지 않는다.**

`acceptance_runtime.py`의 `AcceptanceEvidence`와 `acceptance_evidence("Txx")`가 독립 UUID 산출물을 쓴다. JSON에는 대상 SHA, dirty 여부, 실행 인수, backend/contract/deploy/e2e 관련 소스별 SHA256(이번 실행 165개), tracked diff SHA256, UTC 시작/끝, 시나리오 exit code, setup/call/teardown별 결과, 명령·실행·사건·최종 순번·보고 값·assertion별 결과를 저장한다. JUnit testcase properties에는 독립 ID, JSON 경로, assertion 결과 JSON을 저장한다. teardown 실패도 call 통과와 구분하여 전체 error/exit1로 남긴다. 토큰·비밀번호·DB 접속 문자열은 증거 필드에 넣지 않는다.

원래 `scripts/check-operable-system.py`는 수정하지 않는다. `load_operable_script()`가 기존 CLI/browser helper를 읽기 전용 import할 수 있도록 제공한다. core 시험은 기존 real network fixture를 사용한다.
