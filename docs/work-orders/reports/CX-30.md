# CX-30 — 게이트웨이 메타데이터 기본 한도 50MB

- 기준 main: `3e10974`. 사용자 A안과 13차 지시서에 따라 기본 숫자만 변경했다.
- 구현 준비됨 / 검증 1건 실패로 중단. 14차는 착수하지 않았다.

## 실측과 운전 시간 계산

운영 게이트웨이 SQLite를 SQLite backup으로 일관된 사본에 복사한 뒤 사본을 읽기 전용으로 한 번 열어 측정했다. 원본의 행·귀속·커서·보존 근거를 변경하지 않았다. 사본은 `/tmp/hmi-cx30-measurement/gateway.sqlite3`에 보호 보관하며 Git에 넣지 않는다. 집계 증거는 `evidence/CX-30-metadata-measurement.json`이다.

| 표 | 행 수 | metadata_bytes 합계 |
|---|---:|---:|
| batch_ledger | 9,644 | 8,854,082 |
| source_progress | 1 | 656 |
| missing_ranges | 453 | 1,145,112 |
| loss_intervals | 0 | 0 |
| 합계 | | 9,999,850 |

대기 배치는 0건이었다. 이전 9차 원본 적용 증거(`evidence/CX-27-v9-original.json`)의 4,753개 원장·5,413,421B와 비교하면 수집 4,891건 동안 4,586,429B 증가, 약 **937.73B/건**이다. 이 관측 평균에서 50,000,000 / 937.73 / 3,600 = **약 14.81시간(1Hz)**, 현재 사용량을 제외한 추가 여유는 약 11.85시간이다. 이는 과거 두 시점 사이의 평균이지 모든 배치의 고정 비용 또는 보장 시간은 아니다. 현재 원장만의 평균은 918.09B/행, 전체 메타데이터를 원장 행으로 나누면 1,036.90B/행이다. 손실·재전송·압축 상태에 따라 달라진다.

## 변경과 유지 조건

- `BufferLimits.max_metadata_bytes`: 10,000,000 → 50,000,000.
- deploy 및 gateway CLI에는 별도 metadata 한도 override가 없어 실행 설정 변경은 불필요했다.
- 30분·100,000,000B 대기 배치 한도, 보존·압축·트랜잭션·METADATA_FULL 차단 방식은 유지했다.
- 기본 50MB 경계에서 enqueue 성공, 1B 초과 시 롤백되는 회귀 시험을 추가했다.
- GATEWAY_BUFFER.md에 변경 이유·관측 증가량·예상 운전 시간·안전 차단·서버 archive 미구현을 기록했다. 현재 가역 압축이 있다는 점도 실제 구현과 맞췄다.
- 장기 고정 용량·서버 보관/재조회(CX-27 §3)는 미설계·미구현이다. 한도 상향으로 해결됐다고 표시하지 않는다.

## 검사 결과와 중단

시험은 아래 명령으로 **한 번** 실행했다.

```sh
.venv/bin/python -m pytest tests/unit tests/integration/test_gateway_buffer.py tests/integration/test_gateway_setup.py tests/integration/test_gateway_recovery_bounds.py tests/integration/test_gateway_pipeline.py tests/integration/test_gateway_opcua.py tests/integration/test_gateway_fifo_recovery.py tests/integration/test_gateway_command_launcher.py -q
```

**740 통과 / 1 실패 / 경고 2**, 198.85초. 전체 단위 및 50MB 한도 회귀는 통과했다. 실패는 `test_gateway_fifo_recovery.py::test_1800_capture_fifo_drain_with_live_collection`의 브라우저 사전 점검이다. 로그인 후 태그는 48개 표시됐지만 200 응답의 `/api/v1/screen?` polling 관측이 0건이라 `rendered == 48 and len(browser_polls) >= 2`에서 실패했다. FIFO 본 시험은 이 사전 점검 이후라 통과로 표시하지 않는다. 한도 변경 실패로 단정하지 않으며, 정확한 브라우저 전송/빌드 환경 원인은 추가 조사하지 않았다.

Ruff check와 format --check는 변경 Python 2개 파일에 각각 한 번 실행해 통과했다. 제품 코드나 브라우저 시험 기준을 바꾸어 실패를 숨기지 않았다. 최초 로그는 `/tmp/hmi-cx30-tests.log`에 있다.

앞선 사용자 지시 “이제 또 실패하면 보고서만 작성하고 멈춰”에 따라 추가 시험·복구·14차 구현은 진행하지 않는다. 13차 전체 검증을 완료로 표시하지 않는다.

## 운영 상태

실행 중 프로세스는 기존 10MB 기본값을 사용한다. 지시서 §2.6에 따라 운영 적용은 배포 후 사용자 별도 요청으로 정상 종료·재기동해야 한다. 이번 작업에서는 runtime 중지·재시작·commission·생산 조작·SQLite 초기화·source/generation 생성·공개 DB 변경을 수행하지 않았다. 따라서 공개 수집이 재개됐다고 표시하지 않는다. 기존 130분 runtime 유지/정상 종료 예약은 변경하지 않았다. PR·병합·배포·공개 확인은 Claude 담당이다.
