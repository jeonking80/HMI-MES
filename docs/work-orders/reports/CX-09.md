## 분석 소비 경로 구현·검증

- 보고서는 schema18에서 immutable `capture_clock_evidence`를 원래 gateway/batch/line/source/stream/generation/seq/epoch/digest에 연결한다. SQL은 canonical 기간 후보만 고르고 shared `effective_capture_clock`로 다시 검증한다. 원래 UTC/monotonic 역전 cutoff가 GOOD을 무효화한다. 기존 스키마 및 proof 행이 없는 이전 배치만 이전 alarm assessment 근거로 폴백하며 명시적 UNKNOWN은 폴백하지 않는다.
- SPC는 raw `canonical_utc`로 조회·초 슬롯을 고르되 원래 observation과 원래 배치 identity의 acquired_at 동시성을 먼저 검증한다. 집계용 메모리 복제에만 canonical 시각을 적용한다. 원본 prefix 소실 여부도 canonical 좌표에서 검사해 뒤의 20개로 기준선을 대체하지 않는다.
- `test_reports.py`의 정상 시각 fixture에 기존 알람 정책과 동일한 명시적 analytics 정책을 연결했다. schema18에서 별도 analytics proof가 UNKNOWN이면 알람의 GOOD으로 이를 덮을 수 없기 때문이다. 불명·역전·epoch 변경 기대값은 낮추지 않았다. `test_spc_http.py`는 이미 명시적 정책을 사용하므로 변경하지 않았다.
- `.venv/bin/python -m pytest tests/integration/test_analytics_clock_consumers.py -q --tb=short`: **5 passed, 11.87초**, 실제 폐기형 PostgreSQL 17.
  - 같은 호스트: alarm decisions 0건에서도 trend GOOD 및 report running > 0. 원시 6시간 보관 정리 후 clock proof와 보고 근거 유지.
  - 측정 기반: 실제 DB nonce 발급·수집·소비로 gateway +3.7초, RTT 0.2초를 주입하고 서울 자정의 가동 시간 투영 확인. PLC production_events.occurred_at는 그대로 유지해 생산 수량을 원래 날짜에 배분.
  - SPC: canonical 40개 완전 부분군과 고정 관리한계 일치. 앞 15분 원시 삭제 후 남은 25개로 기준선을 바꾸지 않고 ORIGINAL_PREFIX_RAW_UNAVAILABLE 유지.
  - 원래 acquisition 좌표의 동시성 유지와 다른 실행 identity 격리.
  - 실제 schema17에서 기존 raw SPC와 alarm proof 없는 report UNKNOWN 동작 유지.
- 초기 시험의 이벤트 dict 준비 오류는 계약 Event로 검증해 수정했다. 취득 시각이 서로 다른 1.2 배치는 기존 transport가 이미 거절하므로, 유효한 +3.7초 투영 양성 부분군과 다른 실행 음성 사례로 원본 좌표·소유 검증을 확인했다.
