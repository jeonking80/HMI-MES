# CX-35 — 원래 레시피 기준 운전 속도 조정

## 구현과 기준 변경

SET_PARAMETERS를 RUNNING/PAUSED의 속도 전용 형식으로 확장했다. 원래 실행·같은 recipe_version·변하지 않은 온도·원래 LOAD 속도 ±20%·PLC 1~60m/min 및 configured limits를 모두 만족해야 한다. 기존 parameters_manage 권한과 STOPPED/READY의 새 recipe 설정 형식은 유지한다. 반복 조정 기준을 직전 값으로 이동하지 않는다.

원래 execution.parameters는 변경하지 않는다. PARAMETERS_CHANGED 사건과 원래 command/요청자/전후/기준 설정/버전을 영구 이력으로 저장하며, 요약에는 최종 설정·원래 baseline·전체 이력이 들어간다. 실제 적용 설정이 달라졌다는 명시적 사건 근거가 있을 때만 기존 ‘요약=등록 설정’ 비교를 확장한다. 순서·한도·scope·최종값·실제 APPLIED inbox 본문/hash/완전성 검증을 통과해야 SETTLED다. 수량/누락/미확정 명령/최종 경계 조건은 유지한다. 같은 속도를 다시 지정한 유효한 별도 명령은 상태 변경 없이 성공하며, 허위 변경 사건을 추가하지 않는다.

SQLite storage v3→v4는 source/archived 사건 CHECK를 넓히면서 FK·보존 나이·영구 키/hash·색인·trigger·모든 본문을 보존한다. runtime v3의 immutable history는 source 사건 보존 후에도 성공한 원래 명령 근거와 대조한다. process·사건·이력·감사·요약·결과는 원자적이다. 이전 snapshot과 final/명령 canonical 형태는 유지한다.

문서 SPEED_ADJUSTMENTS.md·PROTOCOL.md와 event/event-page/run-summary schema를 갱신했다. 기존 fake legacy snapshot fixture는 새 PLC 필드도 제거하도록 조정했다.
