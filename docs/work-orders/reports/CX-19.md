# CX-19 — 실제 30분 API 단절·5분 회복 실행기

판정: **미실행(UNRUN)**. 실행기 단위 검증은 실제 30분 단절의 통과 근거가 아니다. 실제 실행 결과는 별도 SHA·dirty·UTC·exit code가 든 JSON 및 원본 JSONL로 남긴다.

## 실행과 사전 고정 기준

```sh
.venv/bin/python scripts/run-outage-acceptance.py --artifacts /tmp/cx19-real-outage
```

사전 빌드한 polling 웹, Chromium/Playwright, Docker PostgreSQL fixture를 사용한다. 공개 DB·공개 배포는 사용하지 않는다. 주 에이전트의 독점 실행 슬롯에서만 실제 실행한다.

- 기존 실제 CLI driver가 별도 PG/API/시뮬레이터/gateway와 암호화 OPC UA, 브라우저 작업지시·LOAD·START를 준비한다. 기본 100ms 공정은 변경하지 않는다.
- 일회성 내부 API 프로세스만 종료하고 새 TCP 연결이 ConnectionRefused임을 확인한 시점부터 실제 1,800초 이상 연결을 끊는다. 시뮬레이터·OPC·gateway 수집은 계속 돌린다. 관측기는 예상된 API 종료만 허용하며 다른 CLI 종료는 실패다. finally에서 원래 args/env·동일 token·동일 PG·동일 log handle로 API를 재실행하고 driver의 children 목록을 교체하여 정리/감독에 포함한다. args/env 값은 출력하지 않는다.
- 48태그·1Hz 수집을 사용한다. 30분 동안 캡처 증가 최소 1,780회(1Hz 스케줄링 여유 20회), 최신 48태그 fresh/DOM usable을 확인한다. 원래 사건을 저장한 시뮬레이터 SQLite와 API inbox의 event_id/전체 body/적용 여부를 대조한다.
- 기본 30분/100,000,000바이트 예산을 그대로 사용한다. 5초마다 큐 바이트와 oldest age를 기록한다. 오래된 payload가 1,802초를 넘으면 실패한다(1Hz 수집 처리 여유 2초). 물리 SQLite/WAL 파일 크기와 payload 회계 크기는 구분한다. 먼저 바이트 한도에 닿았을 때의 손실 기록은 `resources.jsonl`과 최종 JSON에 남긴다.
- 동일 API 재실행 직전부터 실제 300초 안에 pending/inflight 각각 ≤1(계속 수집하는 최신 배치 허용), 원래 사건 반영·연속 커서 ≥재연결 직전 source head·미해결 gap 0·최신 48태그와 화면 회복을 모두 확인한다. API 시작 시간도 300초 budget에 포함한다. source history 원본과 inbox·cursor·gap은 `reconciliation.json`에 저장한다. gateway eviction으로 생긴 샘플 손실을 사건 재조회로 복구했다고 주장하지 않는다.
- hook 종료 후 기존 driver의 PAUSE/END_RUN과 원래 execution 최종 수량/정산 대조까지 성공해야 전체 실행이 성공한다.

## 재사용 방식과 산출물

Claude 소유 `scripts/check-operable-system.py`는 읽기 전용으로 불러온다. 메모리 AST에 RUNNING 시점 callback 하나를 삽입하며 원본 파일을 변경하지 않는다. 고정 anchor가 각각 정확히 한 번 일치하지 않으면 서비스 실행 전에 실패한다. 실제 driver SHA256 및 확장 목록을 수락 JSON에 남긴다. 장시간 생산을 유지할 작업지시 target 20→4,294,967,295, gateway poll .25→1초, 일회성 로컬 service token 1→12시간 만료로 확장한다. 같은 커널에서 실제 구동하는 로컬 stack에 지원되는 `--trend-clock-policy same-host`를 명시한다. 가속 시계·tick/공정 치수 변경은 없다. 단절 중 내부 API를 거치지 않는 실제 operator `/auth/me`와 시뮬레이터 snapshot 조회로 기본 30분 idle timeout을 정상 갱신한다. `tests/e2e/long_run_runtime.py`가 공통 구현이며 `scripts/run-outage-acceptance.py`가 진입점이다.
