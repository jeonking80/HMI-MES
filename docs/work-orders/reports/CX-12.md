# CX-12 서버리스 트렌드 보관 설정

`VercelConfig`가 `HMI_TREND_RAW_HOURS`(0 초과~168시간), `HMI_TREND_MINUTE_DAYS`(0 초과~90일)를 읽어 실제 서버리스 `IngestionService`에 `TrendRetention`을 전달한다. 유한 소수를 허용하고 오류는 값 반영 없이 구성 단계에서 거절한다. 생략하면 기존 7일·90일, 일부 지정이면 나머지는 기본값이다.

공개 환경변수·운영 DB·기존 head14 readiness·서비스 인증·고정 배포 정책은 변경하지 않았다. 코드의 기본 보관 기간도 유지한다. 문서에는 6시간·14일 프로필, 새 원시/분 테이블 추정 0.23~0.42GB와 기존 배치·알람 등 증가 제외에 따른 무료 용량 보장 불가, 오래된 원시 조회 상실을 기록했다.

검증:

- `pytest -q tests/unit/test_trend_retention_config.py`: 42 통과.
- 변경 Python 파일 ruff: 통과.
- `pytest -q tests/integration/test_vercel_retention.py tests/integration/test_vercel_app.py`: 실제 Docker PostgreSQL에서 31 통과(15.63초). 새 head17의 프로필/기본 cleanup 차이·내부 bearer 인증·사용자 세션 조회와 기존 head14 readiness/라우팅 회귀를 확인했다.
- medium 검토 관점: 환경변수는 유한 범위 숫자만 수용하고, 생략/일부 설정 기본값과 오류 거절을 고정했다. 실제 서비스 생성에 검증한 불변 설정을 전달하며, 인증·권한·스키마·시간 품질·삭제 상한은 바꾸지 않았다. 주 에이전트 최종 검토 후 커밋한다.

실제 PostgreSQL 시험은 고정 disposable 컨테이너만 사용하며 canonical14 초기화→명시적 head17 업그레이드/권한 적용→진짜 비특권 `hmi_app` 연결을 검증한다. 운영 DSN과 외부 유료 서비스는 사용하지 않는다.
