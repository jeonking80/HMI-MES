# CX-10 분석 기능 제공 여부

비로그인 `GET /auth/config` 응답에 `analytics` boolean을 추가했다. 기존 `guest_viewer` 필드는 유지한다. 사용자 앱이 CX-01~05 등록을 모두 마쳤고 실제 필수 경로/HTTP 메서드가 모두 남아 있으며 DB가 해당 기능의 스키마를 읽을 수 있을 때만 true다.

분석 스키마는 기존 `TREND_REVISIONS`와 `SUPPORTED_AUTH_REVISIONS` 허용 목록의 교집합에서 정지 사유 테이블이 없는 head15를 제외한다. head14/15는 false, head16/17은 true다. head18도 두 목록에 명시적으로 추가했으며 분석 시간 근거 테이블의 SELECT 권한까지 확인한다. 게스트 head17 마이그레이션 자체는 분석의 필수 조건이 아니다.

DB 확인은 기존 마이그레이션 공유 잠금 아래 읽기 트랜잭션만 사용한다. 스키마 번호 외에도 새 원시·분·clock registry·정지 사유 테이블을 SELECT LIMIT 0으로 확인한다. 업그레이드 후 runtime 권한이 빠졌거나 객체가 없으면 false다. 쓰기 권한은 요구하지 않으며 조회 전용 DB 역할에서도 true가 가능하다. DB 연결/권한 오류는 상세나 비밀값을 노출하지 않고 false로 응답한다. 로그인·세션·감사 기록을 만들거나 사용자 데이터 접근 권한을 부여하지 않는다.

검증:

- `pytest -q tests/integration/test_analytics_availability.py`: 실제 고정 Docker PostgreSQL에서 **17 통과 (11.20초)**.
- head14/15/16/17의 비로그인 응답, 기존 guest 필드, 필수 경로/메서드 10개 각각의 부재, 등록 완료 표식 부재, DB 오류, 누락 객체, 실제 SELECT 전용 역할과 누락 grant를 확인했다.
- 변경 Python 파일 ruff: 통과.
- 기존 guest/Vercel의 정확한 config 응답 비교 시험은 주 에이전트 소유 파일에서 additive 필드에 맞춰 통합한다.

공개 환경·스키마·서버리스 구성·UI·빌드 플래그는 변경하지 않았다. UI가 서버 응답으로 메뉴를 여는 결합은 Claude의 범위다. medium 최종 검토 후 `c88f991`으로 커밋했으며 head18 근거 읽기 권한 검사는 `626e8c6`에 포함했다.

주 에이전트 통합 후 기존 guest/Vercel/분석 제공 여부와 head18 권한 시험 총 54개가 통과했다(32.70초). head18 제공 여부·근거 권한 누락을 포함한18개는 최종 분할 검증의 선행 구간에서도 모두 통과했다.
