## 검증 근거와 범위

- 실제 PostgreSQL/ASGI에서 viewer의 기존 대시보드 GET과 증명 배열을 확인했다. 새 알람 도구는 실제 활성/복귀 미확인 알람을 구분하고, 미지원 설비404를 null로 남기며 알람 인스턴스·조치 기록을 변경하지 않았다.
- 실제 전용 게스트 세션을 새로 발급하며 요청해도 세 번째 요청은429이며, 앞선 두 요청만 mock 공급자에 전달되었다.
- 단위 시험은 전체 시한이 여러 모델 왕복에 걸쳐 누적되고 인증·내부 GET도 포함함을 확인했다. 공급자 HTTP 타임아웃도 동일504 코드로 구분한다. 설정의 NaN/Infinity/비정수·범위 위반과 URL 자격 증명·쿼리를 거절한다.
- caplog의 성공·공급자 오류·시간 초과·내부 도구 오류 경로에서 테스트 프롬프트·답변·키가 기록되지 않음을 확인했다. 실제 비밀값을 사용하지 않았다.
- 전체 프로젝트 회귀·운영 브라우저 검사는 이 작업에서 실행하지 않았으며 통과로 주장하지 않는다. 모델은 모두 mock 응답이고 실제 Nemotron 네트워크 호출은 없었다.


## 최신 main 우선 병합 보완

사용자 지시에 따라 `c681b21`의 main 동작을 기준으로 `assistant.py`와 결합 시험의 충돌을 해결했다. 초기 25초 시한은 현재 50초 전체 시한으로 대체한다. 설정명은 main의 `deadline_seconds` 하나를 사용하고 바깥 요청 시한에도 동일한 값을 적용한다. 단일 공급자 요청은 최대25초·전체 시한 이하이며 NaN/Infinity·범위 오류를 거절한다. HTTP504와 추가 `ASSISTANT_TIMEOUT` 코드는 유지한다.

main의 한국 오늘 날짜 시스템 프롬프트, Nemotron thinking 비활성, 일시적 공급자 오류 1회 재시도, 짧은 남은 예산에서의 도구 없는 최종 응답, 대시보드 모델 입력 축약 및 관련5개 시험을 보존했다. 기존 활성 알람·게스트 계정 공통 제한·로그 보호를 함께 유지한다. UI·README·Vercel 설정은 직접 편집하지 않았다.

병합 후 단위 검증: `tests/unit/test_assistant_bounds.py` **24 passed in 0.78s**. 시한 범위 시험은51초를 거절하도록 갱신했고, 실시간 시한 시험만 테스트 내부에서 짧게 가속하여 main의 정상50초 계획 임계값을 보존한다. 병합 후 PostgreSQL/ASGI 재검증 결과는 아래에 추가한다. 앞선38개 통과 기록은 병합 이전 검증이다.

병합 후 최종 검증: `.venv/bin/python -m pytest tests/unit/test_assistant_bounds.py tests/integration/test_assistant.py -q` → **43 passed in 21.42s**(단위24개 + 실제 PostgreSQL/ASGI19개). main의5개 추가 동작 시험과 기존 알람·게스트·로그·전체 시한 검증이 함께 통과했다. 변경 Python3개 파일 ruff·format 검사도 통과했다. 공급자는 mock만 사용했다. 전체 프로젝트 회귀 결과는 주 에이전트가 별도로 기록한다.
