# CX-03 결과

- 커밋: 주 에이전트가 공유 브랜치에서 작업별 커밋·푸시를 수행한다.
- 상태: 해당 범위 PostgreSQL·ASGI 검증 통과, 별도 high 검토 대기.
- 변경 파일: apps/api/downtime.py, apps/api/downtime_http.py,
  apps/api/migrations/versions/0016_downtime_reasons.py,
  tests/integration/test_downtime.py, docs/architecture/DOWNTIME_REASONS.md,
  이 보고서. auth 권한·사용자 앱·Vercel 등록·공유 상태는 각 소유 담당자가 통합한다.
- 계약 차이: 기존 필드·의미 변경 없음. 명세에 응답 형태가 지정되지 않은 쓰기와
  이력 조회는 전체 스코프·원본 구간·작업자·UTC 시각을 포함한 영수증과
  최신순 items를 반환한다. 메모를 생략하면 빈 문자열이다.
- 감사: 별도 mes_management_audit 변경 대신 동등한 append-only
  downtime_reason_history에 업무 감사·원본 요청·응답을 원자적으로 함께 저장한다.
  UPDATE·DELETE·TRUNCATE 및 사용 후 다운그레이드를 DB에서 거절한다.
- 실행한 검증:
  - `.venv/bin/python -m pytest tests/integration/test_downtime.py -q`:
    **9 passed in 14.36s**, 실제 임시 PostgreSQL Docker 사용.
  - `.venv/bin/ruff check apps/api/downtime*.py apps/api/migrations/versions/0016_downtime_reasons.py tests/integration/test_downtime.py`:
    **All checks passed**.
  - 수정 파일에 ruff format 적용. 전체 저장소 lint·통합 check-local은 주 에이전트가
    병렬 작업 통합 후 실행한다. 이 작업자가 전체 통합 검사를 실행한 것으로 표시하지 않는다.
- 검증 범위: operator·production_manager 허용과 viewer·equipment_admin 거절,
  CSRF 누락 403, 비로그인 이력 401, UNKNOWN 422, 시작 불일치 409,
  UUID 본문·작업자·소스·스트림·실행 충돌 409, 4개 동시 재요청 1행,
  실패 롤백, 이력 보존·최신값, 변경된 경계 사유 미표시와 원본 재요청 영수증,
  자정 절단에 사용하는 구간 포함 검사, 빈 스키마 migration 왕복 및 사용 후 거절.
  실제 수집/coordinator 근거의 타임라인 사유와 일일 EQUIPMENT 3초 합계도 검사했다.
- high 검토: 마이그레이션·권한·격리 별도 high 검토를 주 에이전트가 배정한다.
  검토 결과는 아직 통과로 표시하지 않는다.
- 기준 문서 영향: 기존 정지 사유 요구 구현이며 보관 기본값 등 기준 변경 없음.
- 브라우저 검사 영향: 정지 사유 입력·수정 후 타임라인 최신 사유 및 이력 표시를
  UI 담당자가 실제 서버와 확인할 수 있다. 기존 브라우저 스크립트 수정 없음.
- 남은 범위·제한: 사용자 앱/Vercel 등록과 보고서 콜백 연결은 주 에이전트 통합
  소유이다. 구간 경계가 바뀌면 기존 사유는 이력에만 남으며 새 UUID로 현재 구간에
  다시 입력해야 한다. 원본 영수증 재요청으로 변경된 구간을 새로 덮지 않는다.
