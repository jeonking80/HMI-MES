# CX-39 — 17차 시뮬레이터 storage v4 현장 채널 회귀

## 원인과 수정

CX-35가 storage를 v4, controller runtime을 v3으로 바꾸고 immutable parameter history trigger 두 개를 추가했으나 FieldChannels가 여전히 storage3/runtime2 및 예전 trigger 집합을 요구했다. 새 SQLite에서도 실제 serve가 시작하지 못한 원인이다.

field_channels.py의 정확한 storage/runtime 버전과 runtime_parameters_no_update/delete SQL을 현재 DDL에 맞췄다. Field 자체의 component schema는 계속v3이다. 모르는 trigger·view·virtual table·temp/attached schema 거절, 정확한 Field DDL/이력 검사와 비Field자료 보존 검사는 유지했다. 느슨한 버전 범위나 임의 trigger 허용을 추가하지 않았다.

이 모듈은 외부 source/archived table의 고정 DDL hash 상수를 쓰지 않는다. _nonfield_digest가 각 DB의 실제 비Field DDL/행 값을 이관 전후 비교한다. 새 v4와 v3→v4의 CHECK 문구 순서 차이를 정규화해 검사를 약화하지 않고, 각각의 원래 DDL을 정확히 보존한다.

## 운영 자료 사본

운영 원본은 SQLite mode=ro로 열어 보호된 /tmp 사본을 1회 만들었다. 원본을 SimulatorStorage로 열거나 이관하지 않았다. 사본에서 storage3/runtime2→4/3, FieldChannels 구성/검사 통과, integrity_check=ok와 foreign_key_check clean을 확인했다. 원래 사건10643건의 정확한 prefix와 모든 기존 field table 자료가 보존됐다. 사본의 추가 사건1건은 controller 재시작 복구 기록이다. 원본은3/2·10643건 그대로다. 증거: evidence/CX-39-operational-copy.json.

새 회귀 시험은 진짜 storage-v3 CHECK·runtime-v2 DDL·기존 field-v3 자료의 tmp 사본 이관, 새/이관된 DB의 Field 보호 동등성, unknown trigger/view/virtual 및 변조된 known DDL 거절을 검증한다. 기존3개 시험 파일의 현재 storage/runtime 버전 기대값만4/3으로 맞췄다.

## 최종 집계

첫 넓은 시험은 **1949통과/fixture6실패,1223.34초**였다. 실패는 오래된 storage 버전 기대값1개, 최신 PLC 필드/빈 history table을 남겨둔 가짜 구버전 fixture4개, controller 재시작 사건을 추가하지 않는다고 가정한 신규 사본 fixture1개였다. 제품 추가 변경 없이 실제 구버전 형태와 정확한 재시작 append 검증으로 맞췄다.
