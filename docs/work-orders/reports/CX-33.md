# CX-33 — PLC 목표 양품 수량 자동 종료

- CX-32 `b59869f` 뒤 구현. 운영 runtime·WO-T1·공개 DB·UI는 변경하지 않았다.

## 동작과 계약

새 LOAD_JOB auto_end_at_target은 strict boolean, 기본true다. bind에도 같은 선택을 받아 실제 LOAD 인자에 명시한다. false는 기존 목표 양품+재공 투입 제한과 RUNNING/명시적 END 동작을 유지한다. PLC가 실제 양품 목표 도달을 확인하면 투입을 막고 재공을 정리하며 출력/피드백/속도 정지와 재공0에서 종료한다. pending command·conflict·recovery·안전 입력·fault·mode의 우선순위는 유지한다. 새 CommandRequest/END_RUN ID는 만들지 않는다.

신규 자동 요약은 TARGET_REACHED, 신규 명시적 END는 OPERATOR 종료 원인을 갖는다. 최종 상태 사건·물품/수량·summary·TARGET_AUTO_END 감사 근거가 동일 SQLite 트랜잭션이다. 근거는 원래 성공 LOAD ID/정책/실행/목표/실제 양품·최종 순번·최종 요약 hash·종료 시각과 연결된다. retention은 그 근거를 검증하고, 수동/기존 종료는 기존 성공 END_RUN 증거를 계속 요구한다. API 정산의 원래 execution 귀속·수량·경계·누락·미정 명령 조건은 약화하지 않는다.

## 기존 기록 호환

LOAD 인자 serializer는 새 정책이 원래 없었던 경우 그 필드만 생략해 기존 canonical bytes를 보존한다. 새 ID의 첫 저장에서만 defaulttrue를 명시한다. 옛 ID의 누락 재요청은 옛 canonical을 유지하며, 새 explicitfalse ID에 누락(defaulttrue) 재요청은 충돌이다. 기존 저널을 수정하지 않는다.

기존 정책 없는 accepted LOAD와 PLC 스냅샷은 false로 동작한다. V1 fieldset을 고정해 새 필드 때문에 인식된 구버전이 깨지지 않게 하고 V2는 false/None을 채운다. 과거 final의 알 수 없는 end_reason은 생략해 기존 hash/attestation을 보존한다. 기존 final을 OPERATOR로 추정해 고치지 않는다. ProcessState/ProcessConfig 스냅샷 형식은 변경하지 않았다.

PROTOCOL.md·GOOD_QUANTITY_TARGET.md에 변경 이유와 영향, command-request/run-summary schema export를 반영했다. 기존 명시적 END 검증 fixture는 false를 명시하도록 바꿔 의도를 유지했다. 새로운 기본true/false 시험은 별도 실제 controller 경로로 수행한다.

## 배포 전 Claude 후속

현재 UI의 exact bind/LOAD args 및 실행 요약 parser는 새 필드를 아직 허용하지 않는다. Claude가 optional auto_end_at_target과 end_reason, 기존 legacy 모양을 함께 처리해야 한다. UI 수정 없이 공개 배포하면 bind 영수증을 미확정으로 표시할 수 있다.
