# CX-06 구현 보고

전용 `guest-viewer` 조회 세션, 명시적 계정 provisioning, 기본 비활성 HTTP/CLI/Vercel 설정, PostgreSQL 분산 입장 제한을 구현했다. 공개 배포에서 기능을 켜거나 운영 DB·로컬 상태·기존 고정 정책을 수정하지 않았다.

- 상태: 개별 PostgreSQL·ASGI와 별도 high 검토 통과, 전체 통합 검사 진행 중.
- 변경 파일: `apps/api/auth.py`, `guest.py`, `user_http.py`, `serverless.py`, `__main__.py`, `migrations/versions/0017_guest_viewer.py`, `tests/integration/test_guest_viewer.py`, `docs/architecture/GUEST_VIEWER.md`.
- 계약 차이: 없음. guest POST는 빈 JSON 객체를 받으며 비활성은 허용된 404를 사용한다.
- 기준 문서 영향: 신규 공개 데모 접근성 범위. 기존 일반 계정 정책과 기본 비활성은 유지한다.
- 브라우저 검사 영향: UX-07이 새 config/guest 경로를 사용해야 한다. 기존 로그인 ID·스크립트 변경 없음.
- 남은 범위·제한: 공개 활성화 승인·실제 공개 프록시 검증·UI 결합은 미수행.
- 스키마: `0017_guest_viewer` (`0016_downtime_reasons` 다음). 전용 계정 표식과 IP 창, 기존 auth_audit GUEST 방식 추가. 기존 head14에서는 비활성 인증 경로가 새 테이블을 사용하지 않는다.
- 계정: 새 전용 계정만 생성 가능, 정확한 viewer·비밀번호 로그인/변경 금지·역할 변경 금지, 매 요청 생존 상태와 역할 확인.
- 세션: 절대 30분, 기존 유휴 정책, 비활성 앱에서 기존 게스트 세션 거절.
- 입장: PostgreSQL 전용 사용자 행 잠금으로 전역 50개, IP당 분당 5회, 키 2048개 상한. 메모리·워커 수에 의존하지 않는다.
- 검증: 실제 Docker PostgreSQL에서 `test_guest_viewer.py` 5 통과. 활성/비활성·Origin/본문·역할 오류·재사용 금지·로그인/비밀번호 금지·전체 쓰기 권한과 실제 4개 쓰기 HTTP 403·교차 인스턴스 IP 제한·동시 60요청 상한·절대 만료·GUEST 감사를 확인했다. guest/auth/HTTP 전체 묶음은 최초 실행 56 통과, 1 실패(새 head17에 대한 기존 bootstrap 리비전 목록 통합 시점 충돌); 수정 후 재실행 중이다.
- 정적 검사: 변경 Python 파일 ruff 통과.
- 별도 high 인증 검토: 통과. 독립 최종 검증 근거는 아래에 기록한다.

구체적 인터페이스·운영 절차와 프록시 IP 제한은 [GUEST_VIEWER.md](../../architecture/GUEST_VIEWER.md)를 참조한다.

## 주 에이전트 통합 확인

- 별도 high 인증·DB 검토 **통과, 차단 문제 없음**. 독립 시험15개와 기존 auth/HTTP/subscription/guest 회귀64개, 합계79개 통과. 별도6개 프로세스/NullPool에서72회 경쟁 중50회 허용, 동일 IPv6 경쟁40회 중5회 허용,2048키 제한·동시 만료·잠금 대기 후 만료 재검사·구 토큰 거절·runtime DML 역할·head14 비활성 호환과 감사 downgrade rollback을 확인했다. 결과 `/tmp/guest-high-review/{results,additional,regressions}.txt`.
- 기존 중간 회귀 재실행 결과를 통과로 추정하지 않고 위 독립 최종64개 회귀 결과로 구분한다. 공개 프록시·Neon·Vercel은 접속하거나 게스트를 활성화하지 않았다.

## 최종 인계

공통 API 등록·전체 실행의 fixture 실패 수정·집중 재검증·브라우저 운전·정산·커밋 소스 Compose 결과와 공개 미적용 경계는 [통합 보고](INTEGRATION.md)를 따른다. 전체 프로젝트 완료나 전체 명령 exit0를 뜻하지 않는다.

- 제한 runtime 배포 준비 추가 커밋: `70826f7`. canonical14→명시적17 이관 후 새 객체에만 부여하는 `deploy/neon-kuls-grants.sql`과 절차·3개 실제 PG 시험을 추가했다. 독립 high의9개와 수정한 coordinator1개를 포함해 **13 passed,18.27초**. `pg_temp` 검색 순서 취약점을 수정하고 실제 임시 위조 카탈로그·CREATEDB runtime을 둔 거절 재현도 통과했다. 기존 ACL·역할·default privileges는 보존한다.
