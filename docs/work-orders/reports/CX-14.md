# CX-14 공개 실데이터 경로와 용량 정책

기준: `CODEX_KULS_보강_v2.md` CX-14 및 OPS-01 이후 공개 head17. 공개 수집 gateway가 상시 연결되어 있다고 가정하지 않고, 사용자가 Linux PC 또는 Windows WSL2에서 기존 승인된 영속 runtime을 300/600초만 연결하는 운영 절차를 작성했다. 공개 네트워크·DB·배포 설정·gateway를 실행/변경하지 않았다. 기존 보호된 `.local/commissioning`에도 접근·수정하지 않았다.

산출물:

- `docs/architecture/PUBLIC_DEMO_RUN.md`: 자격 증명 파일 경로, 플랫폼 조건, source 연속성, 정확한 준비/시작/중지/용량 측정 명령.
- `scripts/check-db-capacity.py`: 기존 환경 DSN으로 READ ONLY transaction에서 DB/relation bytes와 행 수 통계 추정만 읽고 오류 상세·비밀값을 반영하지 않는다.
- `tests/integration/test_db_capacity.py`: 실제 PostgreSQL 읽기 전용 모드·metadata-only 출력과 연결 오류 비밀값 비노출 검증.
- `TREND_HISTORY.md`: 짧은 시연 용량/중지 예산 절만 추가했다. 기존 기준 보관·immutable 원본 정책은 완화하지 않았다.

현재 CLI 확인 결과:

- `plant_runtime.py serve`와 gateway CLI는 source-binding 등록을 자동 호출하지 않는다. 기존 head17 scope/인증 정보로 수집할 수 있다. 반면 패키지 `/internal/v1/source-binding`은 head14 전용이므로 공개 head17 자동 등록 명령으로 문서화하지 않았다.
- 고정 공개 scope는 기존 capture ledger와 이어져야 한다. 새 `prepare --initialize`로 같은 source를 다시 만들지 않으며, 승인된 중지 상태의 영속 DB/인증서 이전 또는 별도 신규 등록이 전제다.
- native Windows는 `fcntl`, POSIX owner 검사 및 asyncio signal handler 때문에 현재 지원 경로가 아니다. Windows PC는 WSL2 Linux 파일 시스템/명령을 사용한다.
- 새 supervisor는 추가하지 않았다. 기존 supervisor에 GNU timeout 프로세스 그룹 종료를 결합한다. 295초 후 TERM, 추가 5초 후 KILL로 300초 예산을 제한하며 600초는 595초+5초다. 실제 생산/복구 작업은 정상 사용자 HTTP/콘솔 흐름을 따른다.

용량: 원본 약 6KB × 1Hz = 300/600초 약 1.8/3.6MB, 하루 약 0.5GB다. raw/분 부분 합까지 약 4.0~5.9/8.0~11.8MB이며 알람·감사·생산·head18 proof/nonce metadata·backlog/bloat 등은 별도다. 기존 DB 350MB 이하에서 1회 25MB 계획 여유와 종료 후 최소 100MB 여유를 권장하되 플랫폼/관측 크기로 판단한다. 무료 DB 총량 보장이 아니다. 주기를 무조건 늦추거나 원본·알람·proof를 삭제하지 않는다.

검증 기록:

- 변경 Python 파일 ruff: 통과.
- `pytest -q tests/integration/test_db_capacity.py`: 실제 고정 Docker PostgreSQL **2 통과, 5.12초**. metadata SELECT 실행 시 실제 transaction_read_only=on과 연결 오류 비밀값 비노출을 확인했다.
- 공개 연결/원격 용량 조회·Windows 네이티브 실행: 미실행. 이 문서는 운영자가 검토하고 실행할 절차다.
- 위험 검토: medium 최종 검토는 주 에이전트가 수행한다.

추가 실패 경로 검증: `env -u HMI_DATABASE_DSN .venv/bin/python scripts/check-db-capacity.py`는 exit 1, stdout 0바이트, stderr `Capacity check failed; verify the protected DSN and read permissions.`만 출력했다. 운영자 비밀값이나 드라이버 오류 원문은 기록하지 않는다.
