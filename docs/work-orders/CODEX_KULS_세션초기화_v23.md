## 1. 데이터 수명 모델

**실행 세션**은 공개 runtime(시뮬레이터·게이트웨이)을 시작해서 종료할 때까지의 기간이다.

| 구분 | 대상 | 수명 |
|---|---|---|
| **유지 — 설정값** (세션과 무관) | 사용자 계정·역할·비밀번호 해시, 게스트 설정, 라인·설비·48태그·수집원 등록, 인증서·자격 증명 등록, **품목 마스터, 공정 설정(레시피 버전)**, 알람 규칙·임계값, 정지 사유 코드, 대기열 정책 설정(자동 연결 여부), 시뮬레이터 운전 설정(모드·물리 파라미터 기본값), 스키마 | 영구 |
| **세션 데이터** (종료 시 전부 삭제) | 수집 원본·영수증·시각 근거·probe, 트렌드 원시·분 집계, 생산 사건·event_inbox·실적·정산, 작업지시·배포·실행·실행 연결·대기열 항목, 명령·결과·운전 감사 기록, 알람 발생·조치·판단 기록, 보고서 근거, 보관 종료 기록·ID 세그먼트 | 세션 하나 |
| **로컬** | 시뮬레이터 SQLite(사건·물품·명령 journal), 게이트웨이 SQLite(원장·대기열) | 세션 하나 |

- **사용자 결정(2026-10-26): "세팅값만 저장해. 설정값들은 저장해야 해."** 설정값은 모두 유지하고, 운전하면서 생기는 기록만 지운다. 표에 없는 테이블은 "사람이 미리 정해 두는 값이면 유지, 운전 중 생기는 기록이면 삭제" 기준으로 분류해 보고한다.
- 유지되는 설정이 삭제되는 기록을 참조하지 않게 한다. 예: 공정 설정이 실행을, 품목이 작업지시를 참조하는 FK가 있으면 방향을 확인한다. 삭제되는 기록이 설정을 참조하는 것은 괜찮다.
- 설정 변경 이력(누가 언제 바꿨는지)은 설정과 함께 유지한다.
- 로그인 세션 토큰은 종료 시 무효화해도 된다.

## 2. 할 일

1. **세션 시작·종료 계약**
   - 서버에 세션 개념을 둔다(session_id, 시작 시각, 상태 ACTIVE/ENDING/ENDED).
   - 모든 세션 데이터 행은 session_id를 갖거나, 세션 경계로 일괄 삭제 가능해야 한다.
   - runtime 종료 절차(정상 종료 명령)가 다음 순서로 동작하게 한다:
     1. 새 명령·등록 접수 중지
     2. 진행 중 실행이 있으면 종료 요청과 정산 결과 기록. 결과 불명이면 불명으로 남긴 채 진행하고 새 ID로 재실행하지 않는다.
     3. 세션 요약 1건 출력(로그 또는 파일): 실행 수, 수량, 정산 결과, 불명 건수
     4. 세션 데이터 전부 삭제(공개 DB와 두 SQLite)
     5. ENDED 기록
   - **비정상 종료**(프로세스 사망·기계 꺼짐)에 대비해, 다음 runtime **시작** 때 이전 세션이 ENDED가 아니면 같은 정리를 먼저 수행한 뒤 새 세션을 연다.
   - 삭제는 TRUNCATE 등으로 파일 공간까지 회수되는 방식으로 한다. 행 단위 DELETE 뒤 파일이 커지는 문제(공개 실측 26MB/h 증가, `evidence/CX-44-claude-public-db.md`)를 반복하지 않는다.
2. **세션 중 용량 상한**
   - 세션이 길어지면 여전히 커진다(현재 약 26MB/h). 세션 안에서는 기존 단기 정리(원시 1시간, 원본 3시간)를 유지하되, **물리 크기가 수렴하는지** 확인한다(VACUUM·재사용 포함).
   - 상한을 못 지키면 최대 세션 길이(예: 12시간)를 두고, 그 전에 화면·로그로 알린 뒤 자동 종료 절차를 밟는다. 공개 0.5GB 기준으로 숫자를 계산해 제시한다.
3. **단순화**: 세션이 끝나면 지우므로, 장기 보관을 위해 추가했던 장치를 정리한다.
   - 18~20차의 영구 영수증·ID 세그먼트·보관 종료 범위
   - 시각 불명 구간의 전역 전파(`retention_provenance.expiry_windows`)
   - 세션 안에서 보고서는 원본으로 계산해도 된다. 단, 원본 3시간 정리 뒤에도 보고서 시간이 유지돼야 하므로 실행 종료 시 시간 요약을 확정 저장한다(22차 B의 봉인 요약을 세션 범위로 축소).
   - 제거하는 기능과 남기는 기능을 표로 보고한다.
4. **기준 문서 변경**
   - AGENTS.md, 기획서 §14 보관, 개발계획서 §5.5, README, 아키텍처 문서에 "공개 교육 운영은 실행 세션 단위로 데이터를 보관하며 종료 시 삭제한다"를 반영한다.
   - 이유와 영향을 적는다. 영향 예: 세션 간 실적·보고서·감사가 남지 않음, 원기획 보관 수락 항목은 미충족으로 표시.
   - 세션 **안에서의** 불변 조건은 유지한다. OPC UA 경계, PLC 판정, 결과 불명 처리, 원래 execution_id 귀속, 원자적 저장, 불명을 정상으로 대체하지 않음.
5. **이관과 공개 적용 준비**
   - 추가 방식 이관과 Neon HTTP 배치·권한 배치를 만든다(`cmp` 일치 확인).
   - 공개 DB의 현재 데이터를 첫 세션 정리로 지우는 절차서를 쓴다. Claude가 실행한다.
   - runtime 종료·시작 절차를 운영 문서에 적는다(Codex 기계 기준 명령).
6. **runtime 감시(R2 축소판):** 세션 중 수집이 60초 이상 끊기면 화면과 로그에 "runtime 정지"를 표시한다. 자동 재시작은 가능하면 넣고, 넣지 못하면 이유를 보고한다.

## 3. 시험

- 정상 종료: 세션 데이터가 공개 DB·두 SQLite에서 0행이 되고, 설정값(계정·라인·태그·품목·공정 설정·알람 규칙 등)은 그대로이며, 로그인과 새 세션 시작이 되고, 다음 세션에서 기존 품목·공정 설정으로 바로 작업지시를 등록할 수 있다.
- 비정상 종료 뒤 재시작: 이전 세션 정리가 먼저 일어난다.
- 진행 중 실행이 있는 상태에서 종료: 실행 종료·정산 또는 불명 기록 뒤 삭제된다. 새 ID 재실행이 없다.
- 삭제 뒤 DB 물리 크기가 줄어든다.
- 세션 중 용량: 가속 적재로 최대 세션 길이 동안 상한 이하를 유지한다.
- `tests/unit` 전체, `tests/integration` 전체 한 번에, Ruff·포맷
- `scripts/check-operable-system.py --analytics-dir --guest-dir --extended-dir`(폴링 빌드) 1회. 그 뒤 종료 절차를 실행하고, 다음 시작에서 같은 스크립트가 다시 통과해야 한다.
