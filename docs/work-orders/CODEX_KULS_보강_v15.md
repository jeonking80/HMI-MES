## 1. 근거

13차 실측(`reports/CX-30.md`, 운영 사본 04:32Z):

| 기록 | 행 수 | 크기 | 비중 |
|---|---:|---:|---:|
| `batch_ledger` | 9,644 | 8.85MB | 88% |
| `missing_ranges` | 453 | 1.15MB(9차 압축 후) | 11% |

- 평소 운전에서 늘어나는 것은 원장뿐이다(건당 약 0.94KB). 유실 기록은 통신 장애 때만 생긴다.
- 서버 `ingest_batches`는 `(gateway_id, batch_id)`가 기본 키이고, 받은 배치의 내용 해시와 수신 확인서를 보관한다. 같은 배치가 다시 오면 서버가 원래 확인서로 답하거나 충돌로 거절할 수 있다.
- 배치 ID는 수집마다 새로 만드는 UUID다. 그래서 오래된 ID가 다시 생길 위험은 서버 고유 제약으로 충분히 막힌다.

9차 검토(CX-27 §2-A)의 반대 이유는 두 가지였다: "로컬 영구 ID 충돌 검사가 사라진다", "체크포인트만으로는 연속성 근거가 없다". 이 지시서는 이렇게 답한다.

- **ID 충돌 검사:** 보존 기간이 지난 배치의 충돌 검사는 서버가 맡는다. 보존 기간 안의 배치는 지금처럼 로컬에서 검사한다.
- **연속성:** 지운 구간은 체크포인트 1행(마지막 순번, 누적 해시)으로 대신 증명한다.

## 2. 정리 규칙

원장 행은 아래를 **모두** 만족할 때만 지운다.

1. 상태가 `ACKNOWLEDGED`이고, 저장된 ACK가 서버 수신 확인(커밋 영수증)이다.
2. 수신 확인 시각에서 **보존 기간 7일**이 지났다. 설정값으로 두고, 시험에서는 짧게 줄일 수 있게 한다.
3. 그 배치의 capture_seq가 체크포인트 다음부터 **끊김 없이 이어지는 앞부분**이다. 중간의 미확정·EVICTED·유실 근거 행을 건너뛰고 지우지 않는다.
4. `missing_ranges`·`loss_intervals`가 참조하지 않는다(`report_batch_id` 포함).
5. 대기열(`outbound_batches`)에 없다.

정리 방식:

- 한 SQLite 트랜잭션 안에서 처리한다: 지울 행들의 해시를 누적한 체크포인트 갱신(`ledger_checkpoint`: generation, last_capture_seq, 누적 SHA-256, 지운 건수, 갱신 시각) → 행 삭제 → `metadata_bytes` 감소. 중간에 실패하면 전부 롤백한다.
- 정리는 주기적으로(예: 1시간마다, 1회 최대 N건) ACK 경로 밖에서 실행한다. 수집·전송을 오래 막지 않게 한다.
- 메타데이터 압력이 걸리면 enqueue 전에 정리를 먼저 시도한다. 그래도 부족하면 지금처럼 `METADATA_FULL`로 안전 정지한다.

시작 검증(`_verify`) 변경:

- 지금은 원장이 capture 1부터 끊김 없이 이어져야 한다(`capture != previous + 1`이면 손상으로 판정). 이를 "체크포인트 last_capture_seq + 1부터 끊김 없이"로 바꾼다.
- 체크포인트가 없으면 지금 규칙 그대로다.

유지할 것:

- 미확정·EVICTED 원장, 유실 근거와 그 참조 원장, 보존 기간 안의 원장
- 30분·100MB 대기 한도, 50MB 메타데이터 한도, `METADATA_FULL` 안전 정지
- 결과 불명 시 새 ID 재전송 금지, 원래 ACK 재사용 규칙(보존 기간 안)

## 3. 할 일

1. **설계 문서:** `GATEWAY_BUFFER.md`에 정리 규칙, 체크포인트, 보존 기간이 지난 배치의 충돌 검사를 서버가 맡는다는 점, 변경 이유와 영향을 적는다. 서버 쪽 동작은 기존 `(gateway_id, batch_id)` 고유 제약과 중복 응답을 그대로 쓴다. 서버 변경이 필요하면 멈추고 보고한다.
2. **구현:** `apps/gateway/buffer.py`에 체크포인트 테이블(기존 SQLite 이관 포함), 정리 함수, 시작 검증 변경. 주기 실행은 `apps/gateway/worker.py`에 넣는다.
3. **시험(각 1회):**
   - 정리: 보존 기간이 지난 확정 원장만 지워지고, 체크포인트와 `metadata_bytes`가 맞게 바뀐다.
   - 보존: 미확정·EVICTED·유실 참조·보존 기간 안의 원장은 남는다. 중간에 남는 행이 있으면 그 뒤는 지우지 않는다.
   - 원자성: 삭제 도중 오류가 나면 전부 롤백된다.
   - 재시작: 정리 후 다시 열어도 `_verify`가 통과한다. 체크포인트와 남은 원장이 어긋나면 `BufferCorruption`이다.
   - 장기 용량: 1Hz 24시간 분량(86,400건)을 가속 적재하고 보존 기간을 짧게 두면, 메타데이터가 한도 아래에서 일정하게 유지된다.
   - 중복: 지운 배치 ID가 다시 오면 서버 고유 제약으로 판정된다(통합 시험).
   - 관련 게이트웨이 시험, `tests/unit` 전체, Ruff, 포맷 검사.
   - 브라우저가 들어가는 시험은 폴링 빌드(`VITE_SCREEN_TRANSPORT=polling npm --prefix apps/web run build`)로 돌린다. 13차 실패는 기본 웹소켓 빌드 때문이었다.
4. **푸시:** 커밋 해시만 알린다.
