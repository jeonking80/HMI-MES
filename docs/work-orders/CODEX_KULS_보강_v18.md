## 1. 배경

공개 DB(Neon 무료 0.5GB)는 2026-10-25 10:43Z에 342MB였다.

| 테이블 | 크기 | 보관 |
|---|---:|---|
| `analog_history_raw` | 184MB | 6시간(①로 1시간) |
| `ingest_batches` | 109MB | **무기한** (10월 23일부터 16,984건, 건당 약 6.5KB) |
| `capture_clock_evidence` | 25MB | 무기한 |

수집 원본은 1Hz 운전 시 시간당 약 23MB씩 늘고 지워지지 않는다. 게이트웨이 원장 문제(15·16차)와 같은 구조다. 기존 원칙("원본·증거는 지우지 않는다")은 무료 데모 환경에서 지킬 수 없어 사용자가 바꿨다.

## 2. 삭제 규칙

수집 원본(`ingest_batches`)과 그에 딸린 시간 근거(`capture_clock_evidence`, 관련 probe)를 아래를 **모두** 만족할 때만 지운다.

1. 그 배치의 모든 사건이 속한 실행이 `SETTLED`이거나, 사건이 없는 관측 전용 배치다.
2. 서버 커서(`verified_through_seq`)가 그 배치의 사건 순번을 넘었고, 그 구간에 `stream_gaps`·격리 사건·미결 명령이 없다.
3. 저장 시각에서 **보관 기간 7일**이 지났다. 설정값으로 두고(`HMI_INGEST_RETENTION_DAYS`, 최소 1일), 게이트웨이 원장 보관(2시간)보다 반드시 길어야 한다.
4. 진행 중이거나 정산 대기·불일치(`PENDING`·`MISMATCH`·`CONFLICT`) 실행의 사건을 담은 배치는 기간과 상관없이 지우지 않는다.

**지우지 않는 것:** 실행·실적 집계, 생산 사건(`event_inbox`·`production_events`), 정산 결과와 최종 요약, 작업지시·명령·알람·감사·계정, 분 단위 집계.

**삭제 방식:**

- 정리는 주기적으로 실행한다(예: 수집 요청 중 1분에 1회, 1회 최대 N건). 수집 응답을 오래 막지 않게 한다.
- 지운 구간은 **보관 종료 기록**(gateway, source, stream, generation, capture_seq 범위, 건수, 내용 해시 누적값, 시각, 사유 `RETENTION_EXPIRED`)으로 남긴다. 연속 구간은 합친다.
- **중복 판정:** 보관 종료 구간 안의 capture_seq·batch_id로 배치가 다시 오면 "보관 기간 지남"으로 거절한다(새 사유 코드). 원래 ACK는 더 이상 돌려주지 않는다. 게이트웨이는 2시간 뒤 원장을 지우므로 정상 흐름에서는 생기지 않는다.
- 트렌드·보고서 API는 보관 종료 구간을 "보관 기간 지남"으로 응답한다. 정상 값이나 데이터 없음으로 바꾸지 않는다.

## 3. 할 일

1. 이관(필요하면 0022): 보관 종료 기록 테이블과 정리용 인덱스. Neon HTTP 배치·권한 배치도 만든다(`scripts/render_neon_migration.py`). 기존 데이터는 지우지 않는다.
2. 구현: 정리 함수와 주기 실행, 중복 판정 분기, API 응답의 "보관 기간 지남" 표시.
3. 문서: 위 기준 문서 변경(이유·영향). 특히 "오래된 실행은 원본으로 다시 검증할 수 없다"를 적는다.
4. **시험(각 1회):**
   - 정산 끝난 7일 지난 배치만 지워지고, 미정산·불일치·gap·격리 구간은 남는다.
   - 보관 종료 구간의 배치 재전송은 거절된다. 보관 기간 안의 재전송은 원래 ACK를 돌려준다.
   - 정리 중 오류가 나면 롤백된다. 보관 종료 기록과 실제 삭제가 일치한다.
   - 트렌드 API가 보관 종료 구간을 "보관 기간 지남"으로 응답한다.
   - 가속 적재: 8일 분량을 넣고 정리를 돌리면 원본 행 수가 7일분에서 일정하게 유지된다.
   - `tests/unit` 전체, 수집·정산·트렌드·보고서·게이트웨이 통합 시험 **전부**(바뀌지 않은 파일 포함), Ruff·포맷 검사, `scripts/check-operable-system.py`(폴링 빌드) 1회.
5. 푸시하고 커밋 해시만 알린다.
