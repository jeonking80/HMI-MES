## 운영 원칙

주 에이전트가 의존성과 통합 검증을 조정한다. 서브에이전트는 `gpt-6.1-sol` medium을 기본으로 사용하며, high는 DB 마이그레이션·데이터 격리 등 위험도가 높은 검토에만 사용한다. DEV 항목을 작은 작업으로 나누고 각 결과를 확인한 뒤 후속 작업을 배정한다. 아래 작은 작업의 통과는 상위 DEV나 전체 프로젝트의 완료를 의미하지 않는다.

## 현재 작업

공개 주소는 <https://hmi-mes.vercel.app>이다. 기존 Vercel Hobby·Neon Free를 유지하고, 현재 클라우드에서 별도 설비·게이트웨이를 실행하여 실제 OPC UA 관측 48개와 DB 커밋 ACK를 확인했다. 고정 수집원 등록과 서비스 인증도 공개 API에서 성공했다. 공개 화면의 실제 viewer 로그인·48개 태그 연속 갱신을 확인했으며 추가 유료 서비스나 사용자 수동 SQL·환경변수 입력은 필요 없다. 공개 배포의 생산·종료·정산 전체를 검증한 것은 아니다. 사용 순서는 [작업자 안내](OPERATOR_GUIDE.md), 재개 절차와 실행 환경의 제한은 [설비 연결](../deploy/plant-hosting.md)에 기록한다.

M1의 독립 운전·원본 보관 보호·지속 온도 편차와 M2의 실제 OPC UA→게이트웨이→PostgreSQL 수집·명령·최종 정산 경로를 구현하고 집중 검증했다. M3는 인증·WebSocket 조회·제어 화면, 아날로그 알람 수집·저장·확인/메모와 실제 브라우저를 검증했다. M4는 작업지시 등록·배포·원자적 실행 연결·원래 결과 복구 화면과 수동 실행 조회 API를 검증했다.

최신 전체 로컬 검사는 `0014` 기준 **Python 1,913개 통과(1,060.63초), 웹 65개 통과, 정적 검사·형식 229개 파일·타입 검사·린트·빌드 통과**로 정상 종료했다. 혼합 알람 실행기/실제 고장 파이프라인·ID query 경로·Line 알람 화면·필드 DELAY V3 통합을 포함한다. 기존 WebSocket 의존성 deprecation 경고 2개가 있으며 실패는 없다. 추가 트렌드 T1과 OPC 차단 O1 초안은 포함하지 않는다.

정산된 실행의 기록 보관/다음 작업 준비 화면, PLC 고장 알람 판정·저장, 미연결 작업 취소 API와 필드 관측 주입 첫 단위를 집중·전체 회귀 검증했다. 신규 DB 이관의 독립 high 검토도 통과했다. 현재 취소 화면의 실제 브라우저 검증을 마쳤고, 명확한 취소 거절 후 명시적 새 준비 절차도 검증했다. 혼합 고장 알람 수집과 유효한 ID의 URL 왕복 결함은 수정·독립 검토·전체 회귀를 통과했다. Line 알람 화면은 실제 CLI/PG/Chromium 검증을 통과했고, 필드 DELAY V3는 선별 통합 후 353개 집중 시험을 통과했다. 이번 통합 변경의 전체 회귀를 통과했다. 추가 트렌드 T1·OPC 연결 차단 O1은 사용자 지시에 따라 보류하며 저장소에 통합하지 않았다. 필드 읽기 실패·채널 단절의 실제 결합 검증도 통과했다. 전체 T01~T12, 보고서·트렌드·보관, 성능·8시간 운전·백업/복원 등은 남아 있다. 세부 근거와 미완료 범위는 [수락 시험 대응표](ACCEPTANCE_EVIDENCE.md)에 기록한다.

## 검증 기록

### 첫 통합 검증

- `./scripts/bootstrap-python.sh`: uv.lock 기반 설치 통과.
- `./scripts/bootstrap-web.sh`: package-lock.json 기반 npm ci 통과.
- `./scripts/check-local.sh`: Python Ruff 검사·형식 검사, **92개 시험 통과**, 웹 TypeScript·ESLint·Vite 빌드 통과.
- 시험 구성: 프로토콜 73개 + 태그 9개 + 실제 OPC UA 호환성 10개. 태그 시험의 하위 검증 156개는 별도로 156개 테스트 함수라고 계산하지 않는다.
- `scripts/probe-postgres.py`: PostgreSQL 17.11 임시 컨테이너의 인증된 TCP 연결, UInt64 정밀도·범위 제약, 고유 제약, 트랜잭션 롤백 확인. 컨테이너·볼륨·임시 비밀번호 파일은 회수했다. 업무 DB 마이그레이션 시험과 구분한다.

독립 검토에서 날짜의 숫자 변환, 불리언 자동 변환, UInt64 스키마 경계, 음수 0의 명령 동일성, 모순된 명령 결과 상태를 발견해 회귀 시험과 함께 수정했다.

OPC PoC의 `SubmitCommand`는 `POC_ONLY`로 거절하고 조회는 계약 예제 fixture를 반환한다. 성공 결과 예제와 종료 요약 예제는 실제 운전 결과가 아니다. 인증서는 검증하지만 운영 사용자·역할 인증과 PLC 실행·영속성은 후속 작업이다. 시험 결과를 T01~T12 통과로 옮겨 적지 않는다.

### M1 컴포넌트와 실제 운전 경로 검증

- 위 M1 컴포넌트별 시험 수는 해당 파일의 수집 항목과 대조했다. 이 문서 갱신에서는 `pytest --collect-only`만 실행했으며, 수집 성공을 시험 통과로 계산하지 않았다. 통과 기록은 실행을 확인한 개별 작업과 아래 실제 브라우저 결과에 근거하며 새 전체 suite 합계는 만들지 않는다. 기존 92개·251개 통합 기록은 당시 실행 이력이다.
- [PLC](architecture/PLC.md), [명령 원장](architecture/COMMAND_STORE.md), [제어기](architecture/SIMULATOR_CONTROLLER.md)를 결합해 접수와 실행 성공을 분리하고 원래 ID의 결과를 추적한다. 중복·내용 충돌·재시작 후 미정 명령을 구별하며 timeout이나 재시작으로 새 ID의 자동 실행·자동 START를 만들지 않는다.

- [인증](architecture/SIMULATOR_AUTH.md)과 [HTTP 콘솔](architecture/SIMULATOR_CONSOLE.md)은 계정·세션·초기 암호 변경·viewer 직접 조작 거절·Origin/CSRF·감사를 적용한다. LOCAL 제어도 PLC 안전 조건을 통과하며 앱 A 인증·MES 정산을 대신하지 않는다.
- [실제 OPC UA](architecture/SIMULATOR_OPCUA.md)는 인증서를 검증하는 암호화 TCP 세션으로 실제 48개 읽기 전용 태그·명령 원장·사건·최종 요약을 제공한다. 고정 성공 응답의 PoC와 구분한다. 실제 LOAD_JOB→START→생산→END_RUN·동일 ID/내용 충돌·미신뢰/평문 거절을 검증했다.
- `scripts/check-simulator-browser.py`는 Playwright/Chromium에서 실제 `apps.simulator serve` CLI subprocess·HTTP·OPC listener·공정 ticker를 실행해 통과했다. 화면 클릭으로 로그인·초기 암호 변경·다섯 항목 복구·LOCAL/AUTO·LOAD_JOB·실제 가상 예열·START 생산·PAUSE 정지·원래 START ID 재요청의 중복 방지·END_RUN 최종 수량·현장 대조·작업 B의 초기 수량 0 및 A 최종 요약 보존·로그아웃 후 401을 확인했다. 잡히지 않은 JavaScript 예외가 없고 서버도 정상 종료했다. 자세한 범위와 제한은 [콘솔 UI](architecture/SIMULATOR_CONSOLE_UI.md), 재현 절차는 [별도 실행](architecture/SIMULATOR_RUN.md)을 따른다.

M1의 주요 독립 운전·권한·실제 생산 경로는 확인했지만, 원본 사건의 7일 보관 정리·검증 checkpoint와 명령/알람을 포함한 전체 crash 복구·T09는 남아 있다. 브라우저의 현장 대조는 다음 로컬 작업 연결을 위한 확인이며 앱 A의 MES 정산 완료가 아니다.

### 실제 앱 A 화면·명령 원장·정산 기반

- 실제 Chromium + 일회용 PostgreSQL + 별도 API 실행기로 로그인·초기 암호 변경·재로그인·로그아웃을 확인했다. 등록된 출처·영속 관측을 API를 통해 읽고 UInt64 최댓값·Bad/null·미수신·관측 만료를 화면에서 검증했다. `scripts/check-app-a-browser.py`는 제어된 시험 배치를 실제 수집 서비스에 넣으며 이 브라우저 시험 자체를 OPC 통신 시험으로 표시하지 않는다.

- 명령 원장·일회성 전달 예약·원래 ID 결과 대조: **34개 실제 PostgreSQL 시험 통과(13.18초)**. 검토에서 발견한 잠금 순서 교착, 같은 라인의 다른 스트림을 통한 미정 명령 우회, ID 내용 충돌의 잘못된 확정을 수정했다. 충돌은 영속 latch로 보류하며 원래 ID 조회만으로 다른 내용의 성공을 가져오지 않는다.

- 실제 HTTP·OPC UA·PostgreSQL 경로에서 LOAD_JOB→START→END_RUN과 실적 수집을 연결했다. 실제 PLC 접수 뒤 응답 유실을 주입해 명령별 Submit 1회와 원래 ID 조회로 성공 확정을 확인했다. 별도 claim 응답 유실 시험은 PLC에 전달하지 않은 명령을 재제출하지 않고 결과 불명으로 유지했다. 사용자 운전 HTTP 화면·전체 M2 완료와 구분한다.
- 게이트웨이 CLI는 명시적 `--enable-commands`로 수집과 독립적인 명령 루프를 실행한다. 실제 소켓 CLI와 명령 단위 시험 **32개 통과(16.33초)**. 수집 HTTP 장애 중 명령 조회, 종료 시 작업 취소·연결·버퍼 잠금 회수를 확인했다.
- 종료 요약 대조 기반: **24개 실제 PostgreSQL 시험 통과(10.04초)**. 원래 실행의 영속 사건 경계·수량·설정·counter_epoch·미정 명령을 확인하고 최종 요약 충돌을 보류한다. 다른 실행의 명령 때문에 과거 정산을 바꾸지 않는다. 게이트웨이 최종 요약 수집과 사용자 명령 API의 개별 검증은 아래에 기록하며 실행기·전체 업무 통합은 진행 중이다.

### 결합 브라우저와 실행 조회
