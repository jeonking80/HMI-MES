# HMI-MES 사용자 매뉴얼

가상 포장라인 1개를 감시하고 생산을 관리하는 운영 화면의 사용법이다. 화면의 버튼 이름은 **굵게** 적었다.

- 운영 화면: <https://hmi-mes.vercel.app>
- 대상: 처음 쓰는 사람, 포트폴리오 검토자
- 기준: `main` `193246c` 이후 화면

---

## 1. 먼저 알아 둘 것

### 1.1 시스템 구성

| 구성 | 역할 |
|---|---|
| 앱 A (이 화면) | 감시, 작업지시, 실적, 분석. 클라우드(Vercel + Neon)에서 실행된다. |
| 앱 B (가상 설비) | 시뮬레이터와 가상 PLC. 별도 PC에서 실행되며 OPC UA로만 연결된다. |
| 게이트웨이 | 앱 B의 값을 1초마다 읽어 앱 A로 보낸다. |

두 앱은 DB와 메모리를 공유하지 않는다. **운전 조건과 실행 결과는 PLC가 판정한다.** 화면은 요청만 보내고, PLC의 결과를 확인해 보여 준다.

### 1.2 공개 사이트의 한계

- **게이트웨이는 항상 켜져 있지 않다.** 실연할 때만 켠다. 꺼져 있으면 모든 값이 "최신 아님(`STALE`)"으로 나오고 운전 버튼은 잠긴다. 고장이 아니라 정상 표시다.
- 하루 단위 대시보드는 대부분 "불명" 시간으로 나온다. 짧은 실연 사이에 기록이 없는 시간을 정상이나 정지로 바꿔 채우지 않기 때문이다.

### 1.3 계정과 역할

| 접속 방법 | 할 수 있는 일 |
|---|---|
| **로그인 없이 둘러보기 (조회 전용)** | 모든 화면 조회. 운전·등록·알람 확인은 할 수 없다. 30분 뒤 자동 종료된다. |
| `demo` 계정 | 작업자(operator)와 생산 담당자(production_manager) 권한. 등록·배포·운전·정지 사유 입력 |

- 계정 발급과 비밀번호 초기화는 관리자에게 요청한다. 앱 B(가상 설비)의 계정은 쓸 수 없다.
- 첫 로그인 때는 비밀번호 변경 화면이 먼저 나온다. 바꾸기 전에는 운전 명령을 보낼 수 없다.
- 비밀번호를 바꾸면 다른 기기의 기존 로그인 세션은 해제된다.

### 1.4 화면 읽는 법 — 세 가지 원칙

1. **불명은 불명이다.** 통신이 끊기거나 시각을 확인할 수 없는 값은 "불명", "시간 불명", "품질 나쁨"으로 표시한다. 정상 값이나 0으로 바꾸지 않는다.
2. **접수 ≠ 실행 ≠ 정산.** 요청이 접수됐다는 것과 PLC가 실행을 끝냈다는 것, 실적 정산이 끝났다는 것은 각각 다른 단계다.
3. **결과 불명이면 다시 누르지 않는다.** 결과 불명인 요청은 같은 ID로 결과만 조회한다. 새로 누르면 같은 작업이 두 번 실행될 수 있다.

## 3. 생산 한 번 해 보기 (처음부터 끝까지)

생산은 아래 순서로 진행한다. 각 단계의 결과를 확인한 뒤 다음 단계로 넘어간다.

```
공정 설정 등록 → 작업지시 등록 → 배포 → 배포 기록 확인
  → 실행 연결(작업 불러오기) → 예열 대기 → 운전 시작 → 현재 작업 종료 → 실적 정산 확인
```

준비물: `demo` 계정 로그인, 게이트웨이 실행 중(1.2 참고).

### 3.1 공정 설정 등록

**생산 관리 → 작업지시 · 공정 설정** 화면 위쪽의 "새 공정 설정 등록"에서 한다. 공정 설정은 설비를 어떤 조건으로 돌릴지 정한 것이다. **ID는 직접 칠 필요가 없다.**

1. 둘 중 하나를 고른다.
   - **기존 설정에서 시작:** 목록에서 기존 설정을 고르면 품목, 온도·속도, 다음 버전(예: v2 → v3)이 채워진다.
   - **품목:** 목록에서 고르거나 새 품목 이름을 입력한다. 처음 보는 품목이면 `RCP-품목` 그룹의 v1로 채워진다.
2. 설정 온도(**50~200 ℃**)와 설정 속도(**1~60 m/min**)를 확인한다. 범위를 벗어나면 등록 전에 막는다. PLC가 작업 불러오기를 거절하기 때문이다.
3. "자동 생성 ID" 칸에서 설정 그룹 ID·버전·설정 ID를 확인한다. 직접 고칠 수 있고, 고친 뒤에는 **ID 자동으로 다시 채우기**로 되돌린다.
4. **공정 설정 등록**을 누른다. 등록한 설정은 아래 작업지시에서 바로 선택된다.

이미 쓸 설정이 있으면 이 단계는 건너뛴다.

### 3.2 작업지시 등록과 배포

같은 화면 아래쪽의 "작업지시 작성"에서 한다. 기본값이 모두 채워져 있다.

| 칸 | 기본값 |
|---|---|
| 작업지시 ID | 예정일 기준 다음 번호 `WO-YYYYMMDD-NNN` |
| 공정 설정 | 가장 최근 설정. 목록에 품목·온도·속도가 함께 보인다 |
| 품목 | 공정 설정의 품목 |
| 생산 라인 | 라인이 하나면 그 라인 |
| 목표 양품 수량 | 1,000개 |
| 생산 예정일 | 오늘(한국 시간) |

1. 필요한 값만 바꾼다.
2. **등록하고 바로 배포**를 누른다. 작업지시를 등록하고 이어서 배포까지 요청한다.
   - 배포 없이 저장만 하려면 **작성 중 작업지시 등록**을 누른다. 나중에 목록의 **작업지시 배포**로 배포한다.

> 목표 수량에 닿아도 자동으로 끝나지 않는다. 종료는 **현재 작업 종료**로 요청한다(자동 종료는 서버 작업 예정).

### 3.3 배포 확인과 실행 연결로 이동

배포가 확정되면 작업지시 칸 위에 초록색 안내가 뜬다. **배포 확인 · 실행 연결로 이동**을 누르면 배포 기록을 확인하고 라인 모니터링의 실행 연결 칸으로 바로 넘어간다.

- 아래 "작업지시 요청 기록"의 **배포 기록 확인 · 다음 업무 준비**를 눌러도 된다. 이때는 목록의 **실행 연결 준비**를 직접 누른다.
- 배포 결과가 확인되지 않으면 실행 연결은 잠긴 채로 남는다. 이전 요청 결과를 모른 채 다음 요청을 보내지 않게 하는 장치다.

### 3.4 실행 연결 (작업 불러오기)

1. 배포된 작업지시의 **실행 연결 준비**를 누른다. 라인 모니터링 화면의 "작업지시 실행 연결" 칸으로 이동한다.
2. **실행 연결 내용 확인** → 내용을 확인하고 **실행 연결 · 작업 불러오기 요청**을 누른다.
3. 작업 불러오기 결과가 **실행 완료 기록**(`SUCCEEDED`)이 될 때까지 기다린다(보통 30초 이내).
   - 응답이 늦거나 결과가 불명이면 **원래 작업 불러오기 결과 조회**를 누른다. 새로 요청하지 않는다.

연결 버튼은 다음 조건이 모두 맞아야 풀린다: 정지 상태, 재공 0개, 원격(REMOTE) 모드, 48개 태그의 최신 정상 값(3초 이내). 버튼 아래 회색 문구가 막힌 이유다(6장 참고).

### 3.5 예열 대기와 운전 시작

운전 요청 칸 맨 위의 **단계 안내**가 지금 단계(작업 연결 → 예열 · 준비 → 운전 → 종료 · 정산)와 다음에 할 일을 알려 준다. 눌러야 할 버튼은 노란 테두리로 강조된다. 운전 중에는 목표 대비 양품 진행 막대가 보인다.

1. 작업을 불러오면 설비가 설정 온도까지 예열한다. 안내에 현재·설정 온도가 나온다. 준비(READY) 상태가 될 때까지 기다린다(약 45초 이내).
2. **운전 시작 · 재개**를 누른다.
   - 시작 조건: 준비 또는 일시정지 상태, 자동(AUTO) 모드, 비상정지 해제, 가드 닫힘, 고장 없음, 운전 허용, 실링기 준비 완료.
3. 요청 상태가 **실행 완료 기록**이 되면 운전 중이다. 생산 수량이 올라가는 것을 확인한다.
4. 결과가 확정(성공·실패)되면 바로 다음 명령을 보낼 수 있다. **확정 결과 확인 · 다음 요청 준비**는 결과 기록을 닫을 때 누른다. 결과 불명인 요청은 지금처럼 다음 명령을 막는다.

### 3.6 일시 정지와 종료

- **일시 정지**: 운전 중일 때만 누를 수 있다. **운전 시작 · 재개**로 다시 시작한다.
- **현재 작업 종료** → 확인창의 **현재 실행 종료 요청**: 신규 투입을 멈추고 재공을 정리한 뒤 실행을 끝낸다. **종료가 확정되면 그 실행은 다시 시작할 수 없다.**

### 3.7 실적 정산 확인

1. 종료 후 **원래 실행 기록 조회**로 끝난 실행을 조회한다.
2. 실적 대조가 `SETTLED`인지, 양품·불량·폐기·재공 수량이 맞는지 확인한다.
3. **저장 정산 재확인 후 기록 보관**으로 정리하고 다음 작업을 준비한다.

설비 종료(END_RUN 성공)와 MES 실적 정산 완료는 다른 단계다. 화면도 "설비 종료 기록입니다. MES 실적 정산 완료는 아직 확인하지 않았습니다."라고 구분해 표시한다.

## 4. 화면별 사용법

### 4.1 대시보드

- 날짜(한국 시간)를 고르면 그날의 양품·불량·수율, 가동·정지·불명 시간, 시간대별 생산, 활성 알람, 진행 중인 작업이 나온다.
- 생산 수량은 "수신된 생산 사건(정산 전 잠정)"이다. 확정 실적은 실적 · 보고서에서 본다.
- "설비 데이터 수신이 지연되고 있습니다"는 게이트웨이가 꺼져 있거나 지연된 경우다.

### 4.2 라인 모니터링

- **조회할 라인 · 수집원**에서 `Packaging line 1 · demo-packaging-source-v1 / events-main`을 고른다. 목록이 비면 **수집원 다시 조회**를 누른다.
- 화면 연결 상태가 "화면 갱신 연결됨"이면 정상이다. "화면 연결 확인 필요"가 나오면 **화면 다시 연결**을 누른다.
- 공정 개요, 48개 태그 값과 품질, PLC 하트비트, 운전 요청, 작업지시 실행 연결, 알람이 이 화면에 있다.

### 4.3 알람

라인 모니터링 화면 아래쪽에 있다. 두 종류다.

| 종류 | 내용 |
|---|---|
| 라인 PLC 고장 알람 | PLC에 기록된 고장과 발생 당시 고장 코드 |
| 실링기 아날로그 알람 | 실링 온도 이탈, 공압 부족 |

- 알람을 고르면 **이 발생 사건 확인**으로 발생 근거와 이력을 본다.
- 작업자는 **사용자 확인**과 **조치 메모 추가**를 할 수 있다. 메모 수정은 **이 기록을 기준으로 메모 수정**으로 하며, 이전 기록은 지우지 않고 새 변경 이력으로 남는다.
- 알람 확인은 고장을 리셋하지 않는다. 고장 리셋은 원인 해소 뒤 운전 요청의 **고장 리셋**으로 한다.
- "조회된 알람 없음"은 그 조회 범위에 기록이 없다는 뜻이다. 지금 설비가 정상이라는 뜻은 아니다.

### 4.4 트렌드

- **태그 선택**에서 측정값(실링 온도, 공압, 속도, 모터 전류 등)을 고르고 **조회 기간**을 정한다.
- 값이 있는 구간이 짧으면 자동으로 확대해 보여 준다. **전체 기간 보기**로 전체를 볼 수 있다.
- 수집 시각을 확인할 수 없는 값(시간 불명)은 선으로 잇지 않고 끊어서 표시한다.

### 4.5 실적 · 보고서

| 보고서 | 내용 |
|---|---|
| **일일 운영 보고** | 하루의 생산, 가동·정지·불명 시간, 정지 사유별 시간, 미확인 알람 |
| **작업별 실적** | 실행마다 양품/목표, 불량·폐기, 수율, 정산 상태, 상태 타임라인 |

- 두 보고서 모두 CSV로 내려받을 수 있다.
- 검산 줄 "가동 + 정지 + 불명 = 보고 대상"이 맞지 않으면 그 실행의 시간 값은 확정하지 않는다.
- 불명 시간이 조금이라도 있으면 실적은 "잠정"으로 표시된다(`UNKNOWN_TIME`).

**정지 사유 입력**

1. 작업별 실적의 상태 타임라인에서 정지 구간을 고른다.
2. 사유를 고르고 메모를 적은 뒤 **사유 저장**을 누른다.
3. 작업자나 생산 담당자만 입력할 수 있다. 불명 구간에는 사유를 넣지 않는다. 사유가 없는 정지는 "미분류"로 집계된다.

### 4.6 SPC 관리도

- 실행 하나(최근 7일)를 골라 실링 온도·압력의 부분군 평균과 범위를 본다. 1분이 부분군 하나다.
- **관리한계는 완전한 부분군이 20개 이상 쌓여야 표시된다.** 공정능력은 25개 이상부터 계산한다. 그래서 20분 미만 실행은 "관리한계를 계산할 데이터가 부족합니다"로 나온다.
- 이상 신호는 통계 규칙 4가지(3σ 밖 1점, 3점 중 2점 2σ 밖, 5점 중 4점 1σ 밖, 한쪽 연속 8점)로 판정한다. 머신러닝이 아니다.
- 최근 15분 선형 회귀로 규격 한계 도달 시점을 추정한다.

### 4.7 운영 도우미

- 질문을 입력하면 기존 조회 API로 데이터를 읽어 답한다. 예: "오늘 생산 현황 요약해 줘", "최근 7일 작업별 수율 비교해 줘".
- **조회 전용**이다. 운전·등록은 하지 않는다.
- 답변 아래 "조회 근거" 배지로 어떤 데이터를 읽었는지 확인한다. "조회한 데이터 없음"이면 답을 그대로 믿지 않는다.
- 게스트는 5분에 2번까지 질문할 수 있다.

## 5. 요청 상태 읽는 법

운전 요청과 작업 불러오기는 아래 상태로 진행된다.

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 요청 저장 · 전달 대기 | 서버에 저장됨 | 기다린다 |
| 전달 기록 · 접수 확인 대기 | 설비로 전달됨 | 기다린다 |
| PLC 접수 · 실행 완료 대기 | PLC가 받았다 | 기다린다 |
| **실행 완료 기록** | PLC가 실행을 끝냈다 | **확정 결과 확인 · 다음 요청 준비** |
| 실행 실패 / 명령 거절 / 미전달 만료 | 실행되지 않았다 | 사유 코드를 확인한다 |
| **실행 결과 불명** | 결과를 알 수 없다 | **원래 ID 결과 다시 조회**만 누른다. 새로 요청하지 않는다. |

## 6. 버튼이 안 눌릴 때

버튼 아래 회색 문구가 이유다. 자주 보는 문구와 대처는 다음과 같다.

| 문구 | 이유 | 대처 |
|---|---|---|
| 초기 비밀번호를 변경해 주세요. | 첫 로그인 | 비밀번호 변경 |
| 이 명령을 요청할 역할이 없습니다. | 게스트 또는 권한 없음 | `demo` 계정으로 로그인 |
| 기존 명령의 결과를 확인한 뒤 다음 요청을 준비해 주세요. | 이전 요청 결과 미확인 | **확정 결과 확인 · 다음 요청 준비** |
| 기존 요청의 원래 기록과 결과를 먼저 확인해 주세요. | 배포 기록 미확인 | **배포 기록 확인 · 다음 업무 준비** |
| 전체 48개 태그의 최신 정상 품질과 원본 시각을 확인해야 합니다. | 값이 3초보다 오래됨 | 게이트웨이 실행 여부 확인. 실행 중이면 잠시 기다린다. |
| 최근 수집과 PLC 하트비트 정상을 모두 확인해야 합니다. | 수집·하트비트 지연 | 위와 같다 |
| 현장 모드에서는 원격 명령을 요청할 수 없습니다. | 설비가 LOCAL 모드 | 앱 B에서 REMOTE로 바꾼다 |
| 정지 상태와 재공 0개를 확인해야 합니다. | 실행 중이거나 재공 남음 | 현재 작업을 종료한다 |
| 시작에는 준비·일시정지 상태와 자동 모드, 안전 입력 및 준비 완료가 필요합니다. | 예열 중이거나 안전 조건 미충족 | 준비 상태까지 기다리거나 앱 B 입력을 확인한다 |
| 일시 정지는 운전 중인 현재 실행에만 요청할 수 있습니다. | 운전 중이 아님 | — |

## 7. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 모든 값이 `STALE`, 버튼 전부 잠김 | 게이트웨이가 꺼져 있다. 공개 사이트에서는 정상이다. |
| "등록된 수집원이 없습니다" | **수집원 다시 조회**. 계속 없으면 관리자가 설비 연결을 준비해야 한다. |
| "화면 연결 확인 필요" | **화면 다시 연결**. 반복되면 네트워크나 서버 응답을 확인한다. |
| 작업 불러오기가 "명령 거절" | 공정 설정의 온도(50~200℃)·속도(1~60m/min) 범위를 확인한다. |
| 대시보드가 대부분 "불명" | 실연하지 않은 시간은 불명으로 남는다. 정상이다. |
| SPC에 관리한계가 없음 | 20분 이상 운전한 실행이 필요하다. |
| 로그인 세션이 끊김 | 30분 동안 쓰지 않으면 종료된다. 다시 로그인한다. |

화면의 **작업지시 요청 기록**·**취소 기록**은 이전 요청 결과를 다시 조회하는 보조 기능이다. 설비를 연결하는 입력란이 아니다.
